# 动态剪藏与摘要

绿天 App 的底部「动态」标签按剪藏时间浏览工作区中的 Web Clipper 归档。每张卡片显示标题、剪藏时间和完整 Markdown 摘要。标题来自剪藏文件名，排序优先使用 frontmatter 的 `created`，缺失或无效时使用文件创建时间。空摘要保留卡片。下拉刷新查看新剪藏，向下滚动读取历史。

绿天服务端用实际启动配置的工作区定位 `moments/YYYY/MM/`。已经配置归档的 Web Clipper 部署才会产生这些文件。服务端按实际排序时间分页，文件创建时间回退的旧剪藏也会参与全局排序。每页返回标题、时间、摘要和操作所需的文件版本，移动端列表不下载正文。列表使用绿天现有的服务端连接和 Bearer 鉴权。

## 摘要操作

「重新生成摘要」以归档中的现有正文为输入，替换摘要区块。「删除摘要」清空摘要区块，保留正文和卡片。两种操作先保存工作区 Markdown，再按原上传位置和文件名正常上传更新后的文件。上传目标缺失时照常上传。目标由原上传规则或已有记录定位，流程不探测文件是否存在，亦不搜索、追踪或整理远程文件。整篇删除另行实现。

- [Web Clipper PR #10](https://github.com/lvtian-bot/web-clipper/pull/10) 将最终 Markdown 复制到工作区。同名归档可能加后缀，原坚果云上传仍使用复盘文件的名称。遇到有歧义的旧剪藏，需要用保留的上传资料确认准确对应关系，无法确认时该条目只读。
- [Web Clipper PR #11](https://github.com/lvtian-bot/web-clipper/pull/11) 改为剪藏、生成摘要、上传均使用工作区内同一个文件。Webhook 与提交 API 走 `NutstoreUploader.upload` 的默认目录（`nascence/Collection/`），沿用归档文件名，包括同月同名时的后缀。工作区的年、月不进入坚果云路径。

## 接口与接入状态

`GET /api/moments` 已实现。可传上一页的 `cursor`。绿天接入了 `POST /api/moments/summary`。在未配对 Web Clipper 时，App 保持可浏览，摘要按钮不可用。

Web Clipper 当前的上传接口需要调用方指定完整远程路径，现有抓取入口接收 URL。启用摘要操作需要在 Web Clipper 加一个本机使用、带现有 API Bearer 鉴权的 `POST /api/moments/summary`。绿天的接入约定如下：

1. 请求由绿天服务端发送，包含 `id`（`YYYY/MM/文件名.md`）、`revision`（完整 UTF-8 文件的 SHA-256 十六进制值）和 `action`（`regenerate` 或 `delete`）。Web Clipper 在其归档根下再次校验路径和版本，并串行化同一归档文件的摘要更新。
2. 用现有摘要器和上传器。重新生成时，用仅清空摘要的临时输入调用现有摘要器，提取新摘要后仅替换原文件的摘要区块。直接在已有摘要文件上调用当前 `--force` 会在旧摘要之前插入新内容。保存成功后，用现有上传路径和文件名上传。保存与本服务的同文件上传（含已有首传重试）需保持一致，避免旧版本在更新后覆盖新内容。
3. 文件保存且上传成功返回 HTTP 200 与 `{"status":"uploaded"}`。保存成功、上传失败返回 HTTP 200 与 `{"status":"upload_failed"}`，绿天会重读本地卡片并显示上传失败。无法确认原上传位置、找不到归档、版本冲突或保存/生成失败时，在修改文件前返回相应非 2xx 状态。
4. Web Clipper 实现该接口后，绿天通过 `LVTIAN_WEB_CLIPPER_API_URL` 读取本机服务地址（回环 origin），`LVTIAN_WEB_CLIPPER_API_TOKEN` 传递 Web Clipper 的 API 令牌。两服务仍需指向同一归档根并具备各自存取权限。
