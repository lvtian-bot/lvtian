# 同步算法与流转设计

> 核心文档：详细说明多场景下的三阶段同步流程、状态机流转、总结决策矩阵以及 UI 横幅 (StatusBanner) 优先级。

---

## 1. 核心状态变量定义

应用内文件同步逻辑主要由两个核心状态维度驱动：

### 1.1 `uploadState`（文件持久化上传状态）
- **数据源**：`useFileMetadataStore`（本地持久化，但 `'uploading'` 状态不持久化，应用冷启动时重置为 `null`）。
- **取值范围**：
  - `null`：闲置或最近一次上传成功。
  - `'uploading'`：后台队列正在向云端传输。
  - `'failed'`：网络异常、鉴权失败或其他原因导致的常规失败。
  - `'conflict-failed'`：云端返回 `412 PreconditionFailed`，触发乐观锁冲突标记。

### 1.2 `syncStatus`（页面实时计算的综合状态）
- **数据源**：内存实时计算（由 Hook 或 Screen 维护）。
- **取值范围**：
  - `'checking'`：正在比对网络、配置或云端元数据。
  - `'synced'`：本地与云端哈希一致，完全同步。
  - `'conflict'`：双向不一致或乐观锁失败，存在未解决冲突。
  - `'offline'`：无网络连接。
  - `'not-configured'`：未完成云端凭据配置。
  - `'error'`：重试无效后的阻断性错误。

---

## 2. 三阶段同步流程 (Three-Stage Sync Process)

闪念时间线与待办列表在页面获得焦点或手动下拉时，统一执行三阶段同步流程：

### Stage 1: 环境检查 (Global Environment Check)
1. **离线检查**：调用 `NetInfo.fetch()`，若 `isConnected === false`，中断流程，设 `syncStatus = 'offline'`。
2. **配置检查**：检查 `cloudService.isConfigured()`，若未配置，中断流程，设 `syncStatus = 'not-configured'`。

### Stage 2: 本地修复与救援 (Local Repair & Rescue)
扫描本地已知文件（主文件及所有历史归档），检查其 `uploadState`：
1. **普通失败 (`failed`)**：
   - 自动重试一次上传。
   - 若重试仍失败，加入 `uploadErrorFiles` 失败队列。
2. **乐观锁冲突 (`conflict-failed`)**：
   - **立即触发智能三路合并 (Smart Merge)**：
     - **合并成功**：自动推送到云端，更新 ETag，用户**完全无感知**，状态恢复为 `synced`。
     - **合并失败**：存在跨行冲突，加入 `conflictedFiles` 队列，等待用户介入。

### Stage 3: 全量对账与冲突检测 (Full Sync & Discovery)
通过前两阶段后，执行双向对账：
1. **获取清单**：合并本地文件与云端前缀扫描结果。
2. **逐项对账比对**：
   - **仅本地存在**：触发自动上传。
   - **仅云端存在（或本地物理文件缺失）**：触发自动下载并更新元数据。
   - **哈希一致（且本地物理文件完好存在）**：跳过，标记已同步。
   - **云端更新 (L == S && C != S)**：自动下载云端版本。
   - **本地更新 (L != S && C == S)**：自动上传本地版本。
   - **双向修改 (L != S && C != S)**：触发智能三路合并，合并失败加入 `conflictedFiles`。

## 4. UI 优先级规则与逐一击破策略 (StatusBanner Priority)

当多文件并发或存在复合错误时，`StatusBannerContainer` 遵循严格的优先级呈现：

1. **Offline**（离线状态）—— 最高优先级
2. **Not Configured**（未配置凭据）
3. **Upload Errors**（上传失败队列）—— `uploadErrorFiles.length > 0`
4. **Conflicts**（冲突待决队列）—— `conflictedFiles.length > 0`

**逐一击破交互**：
若队列中包含多个异常文件，Banner 优先提示首个文件（如 `上传失败: flash_notes.md (+2)`）。用户处理或重试完毕后，队列出队，自动切换展示下一个文件，直到全部清空。
