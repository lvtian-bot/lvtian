# 自动任务只读展示

状态：2026-10-26 用户明确将首版收窄为「任务保存在服务器，App 只展示」。本文件替代此前包含管理表单的拟稿；实现仍需统一 PR、云端 Codex 审查，不代表已上线。

## 首版范围

- 底部标签与页面标题统一为「任务」，共用 `tabs.todo` 文案。
- 列表仅显示服务端返回 `status=active` 的任务；隐藏已结束或停用记录，不删除后台任务及执行记录，不凭手机时间自行判断下一次运行。
- 当前仍展示服务端任务名称、执行指令、原生时间规则、明确时区、下一次执行时间和排程状态。手机不保存另一套任务规则，不计算权威下一次目标，不计时触发。
- 待用户确认的布局优化：参考提供的任务列表截图，以任务名称为主、执行时间为辅；完整指令与记录下沉至详情。不照搬目标/追踪分类，也不添加无实际功能的复选框。此项尚未实施。
- 只读入口「触发记录」「查看结果」，允许刷新。
- 首屏「加载中」；失败显示「连接失败」和「重试」；未启用明确显示「服务端尚未启用自动任务」。失败不能伪装空列表；真正空列表为「暂无自动任务」。
- 页面进入、App 回前台、连接恢复时重新读取；丢弃旧服务身份或旧页面请求的迟到数据。

## 状态语义

- active/inactive 是云端排程状态，不是工作的成功/失败；一次性任务不再排程也不能直接称为执行完成。
- 投递状态「未触发」「已投递」与执行结果分开。触发记录证明指令进入持久收件箱，不证明模型执行成功。
- 结果只有真实 turn/end.completed 才显示「已完成」；其他真实失败终态显示「执行失败」，事实不足时显示「执行状态待确认」。
- 未确认实时运行或审批事实时，不伪造「执行中」「等待审批」。
- 仅展示任务对应的 assistant 可见文本，不显示系统提示、思考或工具 schema。截断历史有明确提示。

## 明确不包含

- 不提供新建、编辑、删除表单或按钮。
- 不提供「标记完成并停止后续运行」；这是用户提到的后续可能能力，不是首版承诺。
- 不做 App 写请求、离线排队、本地调度、Google Tasks 接入。
- 不追加主聊天结果通知，不做手机系统推送；它们不是完成只读展示的必要条件。
- 云端原生任务的创建和管理仍由主聊天工具/原生宿主承担，App 不是执行中枢。

## 存储与接口

权威任务规则：`<服务端 dataDir>/native-tasks/home/storages/schedule.json`。

任务会话及结果：`<服务端 dataDir>/native-tasks/home/sessions/`。

默认 dataDir 为 `~/.config/lvtian/data`，若服务配置自定义 dataDir 则随之变化。App 通过已有鉴权入口的 GET `/api/tasks`、`/api/tasks/:id/history`、`/api/tasks/:id/result` 读取，不直接下载和解析内部存储文件。
