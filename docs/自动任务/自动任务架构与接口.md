# 自动任务架构与接口

## 状态与边界

2026-10-26 用户将首版明确收窄为：**任务保存在服务端，App 仅只读展示服务器任务与结果**。云端原生宿主、连接适配、业务服务、鉴权 HTTP、主聊天实际工具桥和 App 只读页面均已有实现及本地验证，尚未合并或生产启用；云端 Codex 审查须在统一 PR 中另行核验。不做 App 新建/编辑/删除/完成停止、不做主聊天结果通知和系统推送。交互范围见 [只读展示说明](界面交互稿.md)。

自动任务与人工待办、Agent 单轮 todo_write 不同。时间规则、下一次运行、持久投递和任务会话均归 DeepSeek Harness 原生 Schedule 所有；绿天不计算权威运行时点、不建立可驱动执行的第二份规则表。

## 服务器存储位置

| 内容 | 位置与归属 |
|---|---|
| 权威任务规则和投递历史 | `<dataDir>/native-tasks/home/storages/schedule.json`，Harness 原生维护 |
| 独立任务会话、执行过程和结果 | `<dataDir>/native-tasks/home/sessions/`，Harness 原生维护 |
| 绿天请求/会话/任务关联 | `<dataDir>/native-tasks/operations.json`，只含关联和指纹，不是第二套任务规则 |
| 父服务元数据独占 | `<dataDir>/native-tasks/metadata-owner.sqlite`，仅租约，不存任务内容 |
| 子宿主存储独占 | `<dataDir>/native-tasks/host-lease.sqlite`，仅租约，不存任务内容 |

默认 dataDir=`~/.config/lvtian/data`；服务配置自定义时以其实际 dataDir 为准。App 只通过现有 Bearer 鉴权的 GET 接口读取，不直接下载/解析内部 JSON/会话日志，也不在手机另存可触发规则。

## 分层与数据归属

- `nativeTaskHost.ts` / `nativeTaskHostRunner.ts`：启动官方 web profile，仅监听回环动态端口。独立根为 `<dataDir>/native-tasks/`，其 `home/` 保存 profile、原生会话/调度/凭据，`agents/` 保存独立全局指令/技能根。`host-lease.sqlite` 只是由宿主进程持有的崩溃安全租约，不保存任务/结果，不调度工作。监督管道断开时宿主退出；两个宿主不能共同写入同一原生 JSON 根。
- `nativeTaskClient.ts`：通过 `/connect` 私有交换进程令牌，以官方 Node Registry/Connection/Gateway + Session/Schedule contribution 调用。原生 owner Cookie 只在内存，不发给手机和主聊天模型。错误仅稳定码；写入超时视为结果未知，不自动重放。
- `nativeTaskRuntime.ts`：父服务生命周期持有独立元数据租约，防止不同端口的两个服务覆盖关联文件；不能仅靠子宿主租约。服务启动时主动拉起宿主，不能等手机首个查询才运行。宿主异常退出后的退避恢复仅管理进程，不触发任务、不补写规则。关闭时先停止接纳并等待服务元数据写入结束，再回收连接/宿主、释放父租约。
- `nativeTaskService.ts`：单 owner 的任务归属、幂等操作和结果读取。`operations.json` 仅保存 SHA256 请求指纹、request/session/task 关联和操作状态，不保存可执行规则/提示词。只有本服务登记的独立根会话可列出或操作；不接受客户端指定任意原生 sessionId。
- `nativeTaskHttp.ts`：沿用既有服务端 Bearer 鉴权和连接入口，返回任务与操作事实；不暴露原生宿主访问凭据。
- `nativeTaskToolBridge.ts`：官方 `defineTool` 注册 `lvtian_task_*`，只薄转接已鉴权任务接口。ACP 通过额外 overlay 加载本地项目插件，不重写用户 ACP profile、不换聊天协议、不安装 MCP Server SDK。工具定义没有凭据字段。

- `src/services/AutomaticTaskService.ts`：App 数据层只提供 catalog/history/getResult 三个 GET 方法，沿用当前服务连接和 SecureStore 凭据加载；拒绝重定向、不排队、不重试，按连接 generation 丢弃旧身份响应。没有手机侧写操作和调度规则。

## 云端创建与未知结果（不在 App 提供表单）

1. 主聊天提交稳定 requestId、名称、指令与明确 at/daily/weekly 规则；同 requestId 不同内容返回冲突。
2. 先取得可用宿主连接，再原子记录新操作指纹、建立独立 standard 根会话；连接尚未成功时不永久占用 requestId。会话 ID 持久关联后才发送稳定 requestId 的创建提示。
3. 任务会话必须实际调用原生 schedule_create。只有 catalog 中存在唯一、归属/名称/指令/规则一致的记录，并在该会话冷读历史查到真实创建工具调用，操作才为 ready。
4. 模型口头答应或 prompt 被接受只算 pending；失去写入响应时为 unknown。进程重启、客户端重连和再次查询仅对账，不盲目再创建。
5. 原生执行不依赖 App、浏览器、绿天的实时事件订阅；任务结果以独立会话的真实事实为准。

请求校验不自写 cron：仅检查字段、日期有效性/未来时点、IANA 时区、时间及 weekday 范围；定时计算由原生负责。

## HTTP 契约

所有入口需既有 Bearer Token。App 首版仅调用表内三个 GET 展示接口；创建/修改/删除及操作对账仅供云端工具链使用，不在 App 暴露。没有启用原生任务时明确返回 503，不伪装空列表；停机避让期间拒绝新的写入，保留查询。

| 方法与路径 | 内容 |
|---|---|
| GET `/api/tasks` | `{tasks}`，只包含绿天拥有的会话任务 |
| POST `/api/tasks` | `{requestId,title,prompt,timing}`；ready 返回 200，pending/unknown 返回 202，均为 `{operation}` |
| GET `/api/task-operations/:requestId` | 对账；200 ready 或 202 pending/unknown |
| POST `/api/tasks/:id/update` | `{expected,title?,prompt?,timing?}`；expected 原样交原生完整预期记录校验，不用最新记录替换以掩盖冲突 |
| POST `/api/tasks/:id/delete` | 原生删除，不撤回已排队消息、不停止已开始工作 |
| GET `/api/tasks/:id/history?limit=&before=` | 原生投递历史，**不是执行成功历史** |
| GET `/api/tasks/:id/result` | lastDelivery 关联的会话结果、终态与可见文本 |

`timing` 为 `{kind:'at',at:RFC3339}`、`{kind:'daily',time,timeZone}` 或 `{kind:'weekly',time,timeZone,weekdays}`。不提供伪暂停、立即运行或手机离线调度。

`result.status` 目前为 not_delivered/unknown/ended；只有真实 turn/end 的 endReason=completed 才可表示执行成功。未读到完成事实时不能据 inactive/lastDelivery 推断成功，也不把持久开放 turn 猜成实时运行或等待审批。结果只返回对应投递 turn 的 assistant 可见文本，不返回系统上下文、工具 schema 或完整 projection。历史读取上限明确标记 truncated。

## 主聊天实际工具

工具名为 `lvtian_task_create/list/operation/update/delete/history/result`。它们调用同一业务服务，不把原生 Schedule 挂到主聊天，不在主聊天的模型队列运行后台工作。创建工具收到 pending/unknown 时，描述明确禁止声称“已经安排”。首版不追加主聊天结果通知，因此不向主聊天事件日志写入后台执行结果、不刷新空闲计时、不将后台过程混入记忆提炼。

ACP overlay 仅写项目模块路径；接口 origin 与 Bearer 只注入 ACP 子进程私有环境。工具桥仅接受数字回环地址、禁止重定向、限制超时/取消。没有手写 MCP 协议或增加服务端 SDK 依赖。

## 配置与部署边界

- `nativeTasksEnabled` 默认为 false；新 CLI 开关 `--native-tasks` / `--no-native-tasks` 写入同一服务配置。提交代码不自动启用，也未更改实机配置或服务。
- 启用时要求既有服务监听回环或通配地址，才能从本机回环进入同一鉴权 HTTP API；不另外开放原生宿主公网端口。
- 任务宿主默认使用 **DeepSeek 官方 API / deepseek-flash**，凭据通过现有受控服务环境继承，不复制主宿主认证文件。主聊天模型不因此迁移或更改。
- 启动时将现有选择的 DSH 权限模式交给原生宿主，不额外提升权限；当前不是“主聊天运行中切权限立即同步全部后台会话”的实现。运行/审批交互仍是上线前待验证项，不能承诺无人值守工作可绕过审批。
- 默认原生会话日志上传与遥测通过宿主管理 overlay 关闭；修改用户管理 overlay 会明确冲突，不静默覆盖。
- 没有拷贝主聊天全部记忆、技能或历史；任务工作目录相同，必要上下文由任务指令明确提供。完整生产能力配置和发布仍需完成验收并走审查/部署流程。

## 验证入口

- `server/test/nativeTask*.test.mjs` 与 `nativeScheduleProbeAssertions.test.mjs`：隔离、幂等、未知写、归属、鉴权、错误脱敏、真实完成态和工具转接。
- `server/scripts/native-schedule-probe.mjs --execute`：真实原生创建 → 断开所有客户端 → 宿主重启 → 到期执行 → 不激活模型的冷读完成事实。
- `server/scripts/native-task-bridge-probe.mjs --execute`：真实主聊天 ACP 工具调用 → 鉴权 HTTP → 独立原生根会话 → 创建工具及 catalog 双证据；不能用纯提示词假装交办。
- `server/scripts/native-task-management-probe.mjs --execute`：真实 daily/weekly 规则、原 expected 更新与冲突、删除、重复 requestId、服务重启后规则/关联恢复及真实结果读取。
- `__tests__/AutomaticTaskService.test.ts` 与 `TodoScreen.test.tsx`：只读 GET、无管理入口、加载/空/错误区分、真实完成状态、分页和连接身份隔离。
- `.github/workflows/pr-check.yml` 同时运行 App 类型/Lint/Jest 和服务端类型/隔离测试，CI 不携带模型凭据。
- 三个模型探针均须先 build，需显式 `--execute` 和受控继承的 DeepSeek 官方 API 凭据；全部使用临时根，不启动生产守护。不得输出启动 URL、Cookie 或密钥。
