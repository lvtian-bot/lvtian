# 后台报告重复重试与主会话超限

## 当前结论与验证范围

故障发生在向主聊天汇报结果时。绿天持久保存了一份后台任务结果，随后多次请求主助理汇报。重试间隔最多 5 分钟，没有次数或时长上限。每次请求把同一份结果作为独立输入写入同一个 DSH 会话，失败后已写入的输入依然保留。队首报告一直待送，后续报告也无法通过严格按序的队列。

已核对生产服务日志、报告数据库、绿天主会话事件和 DSH 底层会话日志，确认失败的汇报输入重复累积、自动压缩失败及会话轮换条件未满足。生产队首报告已单独暂停，原始结果和主聊天历史保留，后续报告仍受生产旧版队列顺序约束。

修复已在任务分支本地通过验证。报告生成有最多三次尝试，认证或额度故障暂停模型生成，提交记录防止向同一会话重复写入。明确超限时通过会话接力为可安全补送的报告换会话一次。生产部署和实际补送待验证。

## 修复与接续

- 采用有界生成退避。共享模型的认证或额度故障暂停所有新报告生成，主聊天成功收到模型回复后恢复，已生成回复可继续补送。单条异常或退避不挡住其他可发送报告。
- 按原生报告 ID 与底层 DSH 会话 ID 持久记录提交。提交后结果不明时不自动重放，已生成的回复继续沿用稳定消息 ID 补送。当前 ACP `session/prompt` 没有报告幂等键，失败可能发生在输入写入之后。
- 明确超限触发独立接力条件。聊天历史保留，用户失败轮由用户决定是否重试，报告在可确认终态且未见工具/审批时最多自动换一次会话。再次超限时暂停报告并保留原始结果。
- 本地回归覆盖跨重启提交记录、持续认证或额度异常、有界重试、旧数据升级、超限接力以及最终消息去重。部署后核对积压报告、主聊天接力和生产日志，再按原生投递身份恢复已人工暂停的队首报告。旧版本已提交但没有写入证明的报告在升级时保留为暂停状态，首次启动不会自动重放。
- Node 22 类型检查及全部 249 项服务端测试通过。使用只读取得的生产数据库副本运行迁移，25 条记录的正文、回复、身份和尝试次数一致，674 次的报告保持暂停，其余两条已完成的报告可以发送。
