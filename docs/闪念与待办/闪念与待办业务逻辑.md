# 闪念与待办业务逻辑

> 本文档规范闪念笔记 (Flash Note) 的文件存储格式、流式时间线追加逻辑，以及助理待办的产品预留说明。

---

## 1. 闪念笔记 (Flash Note) 规范

### 1.1 存储与命名格式
- **核心文件**：默认存储于 `flash_notes.md`。
- **时间戳标题铁律**：每一个独立的闪念条目必须以二级标题加标准时间格式开头：
  ```markdown
  ## YYYY-MM-DD HH:mm:ss

  这是闪念笔记的正文内容，支持任意 Markdown 语法。
  ```
- **格式约束**：禁止使用其他日期格式（如 `YYYY/MM/DD` 或带中文字符的 `2025年`），因为三路合并的时间戳排序与解析器严格依赖此正则：`/^##\s+(\d{4}-\d{2}-\d{2}\s+\d{2}:\d{2}:\d{2})/m`。

### 1.2 追加写入链路
1. 用户在全局模态框 `FlashNoteInputModal` 中输入文字并提交。
2. 调用 `FlashNoteService.addNote(content)`。
3. `FlashNoteService` 构造符合规范的时间戳标题块，追加写入本地物理文件。
4. 立即将 `flash_notes.md` 推入 `useSyncStore` 上传队列（Write-Through）。
5. 触发界面时间线乐观更新与 WebDAV 同步。

---

## 2. 待办 (Todo) 演进说明

- **旧个人待办清理**：原先基于闪念 Markdown 提取个人 Checkbox 任务的专用界面与业务逻辑（`TodoParser`、提取回写等）已退场；闪念原文中的 Checkbox 语法保留原样，不改写用户既有笔记内容。
- **助理待办**：后续待办能力属于绿天个人助理体系（由助理记录、维护和跟进，覆盖人执行、助理执行或双方协作事项），在服务端与跟进规则确认后另行实现。
