# 闪念与待办业务逻辑

> 本文档规范闪念笔记 (Flash Note) 的文件存储格式、流式时间线追加逻辑，以及智能待办 (Smart Todo) 的 Markdown 解析与状态同步规则。

---

## 1. 闪念笔记 (Flash Note) 规范

### 1.1 存储与命名格式
- **核心文件**：默认存储于 `flash_notes.md`。
- **时间戳标题铁律**：每一个独立的闪念条目必须以二级标题加标准时间格式开头：
  ```markdown
  ## YYYY-MM-DD HH:mm:ss

  这是闪念笔记的正文内容，支持任意 Markdown 语法。
  ```
- **格式约束**：禁止使用其他日期格式（如 `YYYY/MM/DD` 或带中文字符的 `2025年`），因为三路合并的时间戳排序与解析器严格依赖此正则：`/^##\s+(\d{4}-\d{2}-\d{2}\s+\d{2}:\d{2}:\d{2})/m`。

### 1.2 追加写入链路
1. 用户在全局模态框 `FlashNoteInputModal` 中输入文字并提交。
2. 调用 `FlashNoteService.appendNote(content)`。
3. `FlashNoteService` 构造符合规范的时间戳标题块，追加写入本地物理文件。
4. 立即将 `flash_notes.md` 推入 `useSyncStore` 上传队列（Write-Through）。
5. 触发界面时间线乐观更新。

---

## 2. 智能待办 (Smart Todo / TodoParser)

### 2.1 支持的 Markdown Checkbox 语法
MDNote 的待办系统是直接建立在 Markdown 纯文本之上的轻量任务管理，支持以下语法标准：
- `- [ ] 待办事项`：未完成任务
- `- [x] 已完成事项`：已完成任务
- 支持嵌套子任务（缩进 2 或 4 个空格）以及行内日期标记（如 `@due(2025-12-31)` 或 `📅 2025-12-31`）。

### 2.2 解析与流转逻辑 (`src/utils/TodoParser.ts`)
1. **纯函数解析**：传入 Markdown 全文字符串，解析出结构化 Todo 项数组（包含 `id`, `text`, `completed`, `dueDate`, `lineNumber`）。
2. **状态更新回写**：
   - 当用户在 `TodoScreen` 点击勾选框时，`TodoParser.toggleTodo(content, todoId)` 精确替换对应行的 `[ ]` 为 `[x]`。
   - 保持文档其余格式、注释及空行完全原样不变。
3. **日历联动**：根据解析出的截止日期，在顶部滑动日历中高亮对应日期的任务徽标与完成度。
