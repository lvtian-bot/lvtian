# 核心架构设计原则：云端为主，按需缓存 (Cloud-First, Cache-On-Demand)

## 1. 核心理念

**"列表即菜单，点击即下单。"**

MDNote 的文件浏览页 (`BrowserScreen`) 被设计为**云端存储的直接映射**，而非本地文件系统的镜像。

*   **唯一真相来源 (Single Source of Truth)**：云端对象存储 (Tencent COS)。
*   **列表渲染**：仅依赖云端返回的文件列表。
*   **本地缓存**：仅作为"上次已知状态"用于加速首屏展示，不参与核心逻辑判断。

## 2. 详细设计

### 2.1 列表渲染 (View Layer)

严禁在列表加载过程中扫描本地文件系统。

*   **流程**：
    1.  **读取缓存**：从 `AsyncStorage` 读取上次的云端列表快照，立即渲染（毫秒级）。
    2.  **网络请求**：后台静默调用 `cloudService.listFiles()` 获取最新列表。
    3.  **更新视图**：获取成功后，直接覆盖当前列表，并更新缓存。
*   **禁止行为**：
    *   禁止使用 `fsService.readDir` 遍历本地目录来生成或补充列表。
    *   禁止尝试合并（Merge）云端和本地的文件列表。这会导致状态竞争和应用崩溃。

### 2.2 文件交互 (Action Layer)

本地文件的存在性检查推迟到用户交互时刻（Lazy Check）。

*   **触发时机**：用户点击列表项。
*   **执行逻辑**：
    1.  **检查本地**：调用 `fsService.exists(path)`。
    2.  **Hit (本地有)**：直接打开 `PreviewScreen`。
    3.  **Miss (本地无)**：
        *   显示加载指示器。
        *   调用 `syncService.performDownload()` 下载文件。
        *   下载成功 -> 打开 `PreviewScreen`。
        *   下载失败 -> 提示错误。

### 2.3 数据流向 (Unidirectional Data Flow)

所有修改操作（重命名、删除、移动）必须优先确保云端状态更新，然后刷新列表。

*   **删除**：云端删除 -> (可选：本地清理) -> 刷新列表。
*   **重命名/移动**：云端更新 (Copy+Delete) -> (可选：本地同步移动) -> 刷新列表。

## 3. 优势

1.  **稳定性 (Stability)**：彻底消除了因本地文件系统权限、路径错误或 IO 异常导致的列表页崩溃。
2.  **一致性 (Consistency)**：用户看到的永远是云端的真实状态，不会出现"本地删了但云端还在"导致的同步困惑。
3.  **性能 (Performance)**：避免了对大量文件的本地 IO 扫描，极大提升了大文件夹下的渲染性能。
