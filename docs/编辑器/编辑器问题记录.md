# 编辑器问题记录

> 本文档记录 CodeMirror 6 嵌入式编辑器在调试、构建与跨端交互中的问题档案与技术约束。

---

## 历史排查档案与技术约束

### 1. 修改编辑器代码后，真机/模拟器不生效
- **现象**：改动了 `src/editor-web/index.ts` 中的逻辑，刷新 App 后没有任何变化。
- **根因分析**：
  1. 未运行构建脚本：RN 端读取的是静态包装好的 `src/editor-web/editorHtml.ts`，而非动态读取 `index.ts`。
  2. Metro 缓存：Metro 打包器可能缓存了旧版的 `editorHtml.ts`。
- **必须保持的技术约束与排障步骤**：
  1. 必须运行 `npm run build:editor`。
  2. 若仍不生效，使用 `npx expo start -c` 清除 Metro 缓存启动。

### 2. 中文输入法 (IME) 输入时长字符与组合键丢失
- **现象**：在 Android 设备上使用部分第三方输入法（如搜狗、微信输入法）输入拼音时，未完成选词就触发了内容同步。
- **根因分析**：
  - CodeMirror 的 `updateListener` 在 IME Composition 阶段会频繁触发 `docChanged`。
- **必须保持的技术约束**：
  - 在监听编辑器变化时，必须检查 `view.composing` 状态；若处于中文输入组合阶段，推迟向 React Native 发送 `CONTENT_CHANGE`，直至拼音选词结束 (`compositionend`)。
