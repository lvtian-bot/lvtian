# 服务端架构与通信协议

## 1. 模块定位与职责

绿天（Lvtian）独立服务端位于仓库 `server/` 目录下，负责在用户的 Windows 或 Linux 宿主机（如 VPS 或个人电脑）上常驻运行个人 AI 助理中枢。

### 核心特性
- **Agent-First 架构（以 Agent 为主，宿主机为辅）**：
  - 记忆系统（`SOUL.md`、`MEMORY.md`、`USER.md`、`AGENTS.md`、`memory/`）与专属工作区统一驻留在 `~/workspace/`，透明可读可控，便于作为独立 Git 仓库进行版本管理与多端灾备同步；
  - 隔离系统级根目录与其他无关文件，杜绝全局扫描造成的 Token 膨胀与误触风险；
- **跨平台独立守护运行**：
  - 基于轻量 Node.js（TypeScript），零外部数据库依赖；
  - 提供标准的后台启停脚本（`scripts/start.sh`, `scripts/stop.sh`）、systemd 单元模板（`lvtian-server@.service`）与 Windows 启动脚本（`start.bat`）；
  - 数据与凭据（`~/.config/lvtian/`）与代码及编译产物完全分离；
- **全天候长连接与状态机对账**：
  - 采用标准 WebSocket + HTTP（Bearer Token 鉴权），网络中立，支持局域网、Tailscale 虚拟内网、公网反代域名直连；
  - 手机断网、切后台或锁屏时，服务端底层任务持续执行并不中断；
  - **热启动极速唤醒（0-RTT Foreground Resume）**：客户端监听 AppState 切回前台事件，后台停留超时主动推倒半开死连接，0 毫秒极速重建并打出握手；
  - **前台优先与退避消除**：用户前台交互时取消惩罚性指数退避（前 3 次重试 0 延迟直接连接），仅在后台断开时保留退避，彻底消除切回前台干等倒计时；
  - **内存热凭证直发**：首次水合后 Token 与 URL 全程保存在内存实例，重连跳过异步 KeyStore/Keychain 解密，握手直发；
  - **心跳假死超时熔断**：心跳周期缩短至 10 秒，发包挂载 3.5 秒熔断计时器，下行超时立即主动判定假死重建，消灭黑洞死链盲等；
  - 手机重新连上时，通过 `sync` 报文上报最后接收序号（`lastSeq`），服务端自动补齐离线期间的增量消息与最新执行状态。

## 3. 通信协议与报文规范

### 3.1 客户端上行报文 (ClientMessage)
- **认证**：`{ type: 'auth', token: string }`
- **对账**：`{ type: 'sync', sessionId: string, lastSeq: number }`
- **发消息**：`{ type: 'chat', sessionId: string, messageId: string, content: string, attachments?: ChatAttachment[] }`
- **撤销排队**：`{ type: 'cancel_queued', sessionId: string, messageId: string }`
- **人工审批反馈**：`{ type: 'approval_response', approvalId: string, approved: boolean, reason?: string }`
- **停止执行**：`{ type: 'stop', sessionId: string }`
- **心跳**：`{ type: 'ping' }`

### 3.2 服务端下行报文 (ServerMessage)
- **认证结果**：`{ type: 'auth_result', success: boolean, serverInfo?: { version, workspace, assistantName } }`
- **对账结果**：`{ type: 'sync_result', sessionId, messages, taskState, pendingApproval, pendingApprovals, currentSeq }`（`pendingApprovals` 为待审批队列全量，`pendingApproval` 为队列首项的兼容保留字段）
- **受理回执**：`{ type: 'message_ack', messageId, seq, status?: 'sent' | 'queued' | 'error', role?: 'user', content?: string, attachments?: ChatAttachment[], error?: string }`
- **流式事件**：`{ type: 'event_chunk', seq, sessionId, messageId, delta, toolCall, status, timestamp? }`（`delta` 为流式增量文本；`toolCall` 携带工具活动状态；占位事件携带服务端创建时刻 `timestamp`，客户端据此建助手消息，不依赖设备时钟）
- **审批申请**：`{ type: 'approval_request', seq, approvalId, prompt, toolName, params }`
- **状态同步**：`{ type: 'task_status', seq, sessionId, state, error, stopReason?, completedAt? }`（`error` 为稳定错误码，客户端按码本地化；`stopReason` 为引擎结束原因，如 `max_tokens` 截断提示；`completedAt` 为任务自然完成时的实际物理时间戳）
- **删除通知**：`{ type: 'message_deleted', sessionId, messageId }`（排队消息撤销时从持久化记录彻底移除并广播多端即时剔除）
- **心跳回执**：`{ type: 'pong' }`
- **回复归属**：`AssistantMessage` 增加可选 `replyTo`，值为该条回复实际回答的用户消息 id。服务端在受理即时消息和从排队队列取出消息时写入；客户端工作记录据此归轮，不能假设“回答前最近一条用户消息”就是它回答的请求。
- **正文/工具顺序与完成时刻**：`AssistantMessage` 增加可选 `toolCallPositions: Array<{toolCallId, textOffset}>`；偏移是工具首次出现时 `content.length`（JavaScript UTF-16 单位），只在新调用登记时追加，后续输入/输出及状态更新不移动位置。仍以 `content` 和 `toolCalls` 为完整文字、工具数据的唯一来源，不复制正文或拆分任务消息身份。实时 `event_chunk` 保持原契约，客户端按相同事件顺序记录位置；`sync_result` 下发服务端持久化的完整锚点。同时 `AssistantMessage` 支持可选 `completedAt`，记录任务完成时的真实时间戳，客户端在分段展示时将最后一段正式答复精准绑定至 `completedAt`，前面的过程文字保留最初 `timestamp`。

### 3.3 附件传输与存储规范 (ChatAttachment)
- **附件数据结构**：
  `{ type: 'image' | 'file', name: string, mimeType?: string, size?: number, uri?: string, data?: string, content?: string }`
- **传输上限与报文配额**：
  服务端 WebSocket 与 HTTP 请求体均配置 30MiB 传输上限（`30 * 1024 * 1024` 字节）；移动客户端单附件读取上限为 10MiB（超限沿用已有提示）。附件合计预算为 20MiB，由 `src/utils/attachmentBudget.ts` 计算序列化附件数组的真实 UTF-8 字节数，包含多字节文本、JSON 转义、Base64、元数据及数组结构，不再用文件大小乘系数估算。选择加入草稿、客户端发送、手动重试及离线队列重新读取后均校验，超限不发送；重试保留原失败消息，离线队列标记该条错误并继续后续消息。其余约 10MiB 为正文与外层报文预留，不代表对无限正文的传输保证；本次不增加独立正文限额。
- **二进制文档工作区落盘**：
  非纯文本附件（PDF、Word、压缩包等）由服务端落盘至工作区 `attachments/${Date.now()}_${random}_${fileName}`，以时间戳与随机后缀防覆盖，并在 prompt 中注入隔离路径与原文件名；若写盘异常（如磁盘满）显式抛出错误中断任务，杜绝静默失败。
- **多模态与长期上下文维护**：
  图片直接转换为 ACP 原生 `image` block，声明类型与 Base64 编码严格对齐；文本附件内容内联入提示词代码块，在历史对话提取（`getHistoryDialogue`）与会话接力原文锚定（`getVerbatimExcerpts`）中自动保留附件内容；为防止用户 Token 与上下文爆炸，历史会话接力仅重放文本锚定，不向后续会话级联重放历史图片。
- **客户端轻量持久化与离线重试**：
  移动端持久化聊天记录时自动剥离附件的 Base64 `data`，仅持久化元数据与本地文件路径 `uri`，杜绝触碰 AsyncStorage 单条 2MB 限制；网络离线重试时优先从本地 `uri` 重新水合文件数据。

## 4. 引擎调度与运维安全细节

### 4.1 执行模型：ACP 常驻引擎
- **常驻长连接**：服务端经 `AcpEngineManager` 以 `dsh --profile acp` 子进程驱动 AI 助理（stdio JSON-RPC 长连接，ACP v1 协议；客户端协议栈为官方 `@agentclientprotocol/sdk`）。引擎懒启动——服务端启动不拉引擎，首个会话请求到达时 spawn 子进程并完成 `initialize` 握手，此后子进程常驻，单连接承载全部会话；连接断开后各进行中任务走错误终态，下次请求自动懒重启；
- **本地二进制直调**：服务端通过 `createRequire` 精准定位 `server/node_modules/@deepseek-ai/dsh/lib/bin.js`，以 `process.execPath` 直接调用，杜绝子进程 `cwd` 脱离服务目录时 `npx` 回退联网下载或查找缓存；
- **会话映射与恢复**：沿用 `SessionManager` 的 dsh 会话绑定（`dshSessionId` 持久化）。同一连接内的活跃会话直接复用；引擎重启后连接重建时经 `session/resume` 恢复持久化会话上下文；恢复失败（含旧 headless 会话 ID 在 ACP 引擎侧不通用）自动新建会话并更新绑定，历史消息仍在服务端日志完整可查；**resume 返回的会话 ID 与请求不一致时（旧日志损坏被引擎自愈替换）按「断档」处理**，补注摘要与最近原文，不在新会话里静默失忆；
- **上下文按轮装配**：`SOUL.md`、`MEMORY.md`、`USER.md` 属于请求期数据，每轮执行前重新读取并重建 prompt 前缀；引擎进程常驻期间用户修改记忆，下一轮即生效，不再冻结在引擎启动时刻；
- **事件流映射**：`agent_message_chunk` 追加会话消息并广播 `event_chunk` 流式增量（ACP 流即已提交文本，无旧 headless 的 8 KiB 截断与 `final` 校准问题）；`agent_thought_chunk` 置思考中；`tool_call` / `tool_call_update` 映射为 `ToolCallState` 广播工具进度（智能提取命令行 `$ cmd`、文件路径等语义化摘要与结构化输入输出，杜绝裸 `bash` 标签；按 `toolCallId` 独立记账收尾，允许工具重叠执行，异常时进行中工具统一终态化为失败）；`session/prompt` 返回的 `stopReason` 终态化任务（`end_turn` → `completed`；`refusal` → `error`；`max_tokens` → `completed` 并随 `task_status.stopReason` 透出，由客户端本地化截断提示）；
- **运行中人工审批**：引擎经 `session/request_permission` 发起审批，服务端映射为 `approval_request` 广播并登记待审批队列；移动端按登记顺序逐卡展示、各自应答，`approval_response` 按 `approvalId` 路由回引擎（并发审批互不覆盖）。单一同意/拒绝意图优先匹配「仅本次」选项，防止扩大为持久授权。审批挂起超过阈值（默认 5 分钟，环境变量 `LVTIAN_APPROVAL_TIMEOUT_MS` 可覆盖）自动拒绝并将任务终态化为 `stopped`；
- **停止与强制回收**：`stop` 报文触发 `session/cancel` 并立即终态化进行中消息（稳定错误码 `task_stopped`）；引擎对取消无响应（进程或工具卡死）时，2 秒后强制关闭引擎连接兜底（回收计时器按被停止的执行身份绑定，不误杀同会话的后续请求）；
- **错误码契约**：用户可见消息错误已稳定码化（`task_stopped` / `approval_timeout` / `engine_refusal` / `engine_error` / `task_cancelled` / `service_restarted`），持久化与广播均存码，客户端按码本地化渲染（i18n），未知码按原文兜底显示（兼容历史中文消息数据）；
- **并发消息排队流水（Queueing）**：引擎执行中（`processing`/`awaiting_approval`）收到新消息时不再拒收报错，而是以 `status: 'queued'` 存入会话并广播排队受理回执；当前任务自然收尾（`completed` 或 `error`）后自动依 FIFO 顺序唤醒下一条排队消息推进执行；收到 `stop` 终止指令时，运行中任务与会话内所有排队消息一并标记为 `task_stopped` 终止；服务重启时未执行的排队消息自动修复为 `service_restarted`。
- **进程安全与连接容错**：
  - WebSocket 服务端及连接级均挂载 `error` 监听，防止超限 payload 或非法帧抛出未捕获异常导致守护崩溃；
  - 启停脚本（`start.sh`、`stop.sh`）严格基于 NUL 字符边界逐项全等匹配命令行参数（必须有独立参数全等于 `${SERVER_DIR}/dist/index.js`），自动清理陈旧无效 PID 文件，杜绝仅包含子串或备份文件名导致的误伤。

### 4.1.1 后台任务结果汇报

- 原生任务仍由独立 Harness Schedule 执行。`nativeTaskReporting.ts` 只做结果对账与可靠投递：官方 control 投影流唤醒，启动/重连与 15 秒恢复 tick 经原生 history/getResult 查事实；`reports.sqlite` 为持久收件箱/发件箱，不存规则或触发任务。
- 固定 `main` 接收完整结果；用户执行、交接、审批和真实用户排队优先。经同一个 ACP 主代理真实回复后，先持久化生成结果，再以 delivery 派生稳定助手 ID 写主聊天；输入不伪装成用户消息，手机只看到主代理输出。
- 报告专用 `persistDurableMessage` 在确认送达前做日志文件 fsync，POSIX 另做目录屏障；失败保留 outbox 回复，重启可幂等续送。Windows 不支持 Node 目录 fsync，不承诺与 POSIX 相同的元数据断电保障。
- `source=task_report` 不刷新真实交互时间，也不按主人提前归来清除提要；已有预生成提要追加完整新报告并持久化。实际助手报告带 `source=native_task_report` / `reportDeliveryId` 进入历史及后续记忆提炼，后台过程不进入聊天。
- 上游 ACP 不提供每轮禁工具/system-message 能力；后台来源为应用层可信封装，任务正文为不可信数据。提示词禁工具、出现工具即中止/审批拒绝是风险缓解，不是执行前硬隔离。详细状态机、失败/未知/大报告边界与验收见 [自动任务模块](../自动任务/自动任务架构与接口.md#结果交给主代理与可靠汇报)。

### 4.2 会话存储：追加式事件日志
- **存储布局**：`sessions/<sessionId>/` 目录承载 `events.jsonl` 活跃日志与 `seg.NNNNNN.jsonl` 轮换封存分段；新系统只维护标准事件日志格式，无历史包袱；
- **追加式写入**：每条状态变更追加一行 JSON 事件（消息新增/整条更新、流式增量、任务状态、dsh 会话绑定、序号推进），写入代价恒定、与历史长度无关，取代旧版「每次变更整文件全量重写」；流式增量内存即时生效、300ms 防抖合并落盘，崩溃窗口由重启修复兜底；
- **快照与轮换**：活跃日志增量超过 4 MiB（环境变量 `LVTIAN_SESSION_ROTATE_BYTES` 可覆盖，测试用小阈值轻量触发）时轮换——旧日志封存为不可变分段，新日志以全量快照头开始，并保留最近 10 个轮换分段（~40MB）防止磁盘无上限膨胀；重启加载只读活跃日志（快照＋其后事件），历史分段无需读入；
- **快照结构（v2）**：快照以完整 `state` 对象承载全部会话字段（替代早期手工挑选字段的平铺结构），新增字段自动随快照持久化，不会再因漏改快照而在日志压缩时丢数据；无 `state` 的 v1 快照仍可正常重放；
- **崩溃自愈**：末行撕裂丢弃并就地截断清理、中段损坏停止该文件重放；轮换中途崩溃（活跃日志未落位）时按序重放全部分段恢复并补写合法快照头；
- **重启修复语义不变**：`processing`/`awaiting_approval` 重置为 `stopped`，流式中断消息标错并推进 seq，修复结果同样以事件追加落盘；
- **内存策略**：消息全量驻留内存（聊天消息体积小，写入放大这一真正失控项已由追加式日志解决）；引擎侧上下文增长由 dsh 内置的自动压缩兜底，服务端不引入额外窗口化机制。

### 4.3 底层引擎会话管理：基于人脑记忆模型的生命周期轮换
- **两层解耦**：手机端与服务端的永续主聊天（持久会话）与底层 DSH 的计算会话（消耗品）完全解耦；
- **双重门禁（AND）**：空闲满 3 小时 **且** DSH 上报的上下文占用达到窗口 20%（100 万窗口即 20 万 token）才允许轮换；容量以 DSH `usage_update` 为准，本地字符估算仅在其尚未上报时兜底；
- **预生成与生效分离**：空闲到 2 小时 55 分（门禁前 5 分钟，可用 `LVTIAN_CONSOLIDATION_LEAD_MS` 调整）就由服务端直调模型生成《前序交流背景提要》；3 小时才允许切换；若主人在 2h55~3h 之间回来，先确认旧会话仍可复用才丢弃提要；若旧会话已被替换，则保留提要并注入替代会话；
- **判定时刻**：3 小时以主人消息到达服务端的时刻计算，不受建引擎耗时影响；
- **提炼输入**：覆盖服务端保存的全部会话历史，不按消息条数或 DSH 周期截断；仅支持 100 万窗口的模型（小于 100 万不在支持范围）；单次预算 50 万字符，超出时分段提炼再合并，不丢中间内容；提炼模型默认 `deepseek-flash`，可用 `DEEPSEEK_MODEL` 覆盖；
- **失败重试**：轮换已开始但 prompt 未送达时保留摘要与「交接未完成」标记，下次请求重新注入，只有交付成功后才清理；
- **记忆与连续性**：换会话时注入「提要 + 最近 8 轮原文锚定」；提要是派生的一次性交接条，真实对话永久留在服务端会话历史中，下一次提炼直接读历史；
- **详细设计**：完整认知模型、判定边界与状态流转参见 [基于人脑记忆模型的会话轮换设计.md](设计/基于人脑记忆模型的会话轮换设计.md)。

### 4.4 统一会话交接总线与 DSH 权限管理
- **架构定性**：DSH 是绿天系统的核心依赖与原生执行引擎；所有导致底层 DSH 会话新建的场景（自动闲置轮换、主动切换权限/重置任务、异常日志损坏自愈）必须全部收拢到统一的**会话交接流水线（Handover Pipeline）**；
- **即时提炼（On-demand Consolidation）**：主动切换权限或重置会话时，服务端立即调用 `contextConsolidator.consolidateNow(sessionId)` 对前序完整对话执行即时提炼，产出最新的《心智接力备忘录》（300~500字：核心共识与最终盘面、未竟事项下一步、主人新定规矩态度、关键实体状态），并落盘为交接快照；
- **四层全量注入**：底层新建会话开局，Prompt 无条件拼装：工作区记忆档案（SOUL/MEMORY/USER）＋《心智接力备忘录》＋关键问答原文锚定＋当前提问，确保心智与上下文 100% 连续；
- **DSH 官方配置直管（SSOT）**：权限唯一真相归于 DSH 自身配置。服务端通过 `dshConfigManager` 直接维护 `~/.dsh/profiles/acp/cordis.patch.yml` 中的官方标准补丁：`sandbox-policy.mode`（`workspace-write` 安全工作区模式 / `danger-full-access` 完全权限模式）与 `approval.policy`（`ask` / `never` 免审批联动），并在引擎启动时注入环境变量 `DSH_PERMISSION_MODE` 实施双重保障；自动兼容并平滑迁移历史非标 `sandboxPolicy` 条目；
- **DSH 模型选择直管（SSOT）**：助理模型唯一真相同样归于 DSH 补丁配置。`dshConfigManager` 同步维护 `cordis.patch.yml` 中官方标准补丁 `acp`（每个 ACP 新建会话使用的 provider/model）与 `agent-default-model`（各入口共享默认模型）的 `provider`/`model` 字段，条目既有其它配置字段（如 `sessionListPageSize`）原样保留；读取当前选择时优先 `acp` 条目、其次回退 `agent-default-model` 条目；可选项清单由服务端常量 `MODEL_OPTIONS` 统一维护并经接口下发（当前为 `deepseek-official/deepseek-flash` 与 `openai-codex/gpt-6.1-sol` 两项），App 侧不硬编码；模型变更仅对之后新建的 DSH 会话生效，故切换时同步触发 `triggerHandover('main', 'model_switch_to_...')` 立即接力；
- **API 与协议对接**：
  - `GET /api/permission`：返回当前服务端生效的 `permissionMode`；
  - `POST /api/permission`：原子更新 DSH `cordis.patch.yml` 并触发 `triggerHandover('main', 'permission_switch_...')`，安全释放旧引擎并无缝重连；交接结束后显式唤醒聊天队列，推进交接窗口内被任务运行门禁排队的消息；
  - `GET /api/model`：返回当前助理模型（`provider`/`model`，优先读 `acp` 条目并回退共享默认条目，均未记录时呈现默认选项）与服务端下发的可选项清单 `options`；
  - `POST /api/model`：校验目标组合必须来自下发清单（否则 400 `PARAM_INVALID`），原子更新 DSH 模型补丁并触发 `triggerHandover('main', 'model_switch_to_...')`；交接结束后显式唤醒聊天队列，推进交接窗口内被任务运行门禁排队的消息（与权限切换、会话重置同一处理）；与权限切换同门禁——有实际变更且任务执行中时返回 409 `TASK_RUNNING`，幂等重放（配置已一致）放行返回 `changed: false`；
  - `GET /api/skills`：扫描并返回服务器已安装的技能列表（名称与中英文简介）；
  - `POST /api/session/reset` 与 WS `reset_session`：手动重置会话上下文，直接调用 `triggerHandover(sessionId, 'manual_new_session')` 完成即时记忆提炼、注销并新建底层 DSH 会话；
  - `GET /api/info`：响应中携带 `permissionMode`，供客户端一次握手获取当前权限状态；
  - 移动端「AI 智能体配置」页以标准设置行（显示当前值，点击弹出底部选择弹层）统一承载执行权限与助理模型两项远程设置，两设置共用同一套远程设置状态机（`useAgentRemoteSetting`：本地持久化秒显、连接后核对、切换二次确认与超时核对；切换完全权限触发高危确认，任务运行中拦截）；
- **设置边界与独立生效原则**：
  - 严格区分客户端本地设置（服务地址、Token 登录凭据，点击保存时仅持久化本地凭据并重连）与服务端远程管理设置（DSH 权限模式与助理模型，在选择确认后独立向服务端发起请求并当场生效并完成会话交接）；
  - 严禁将远程管理操作与本地登录表单混合打包提交，各设置项独立修改、独立确认、当场生效。

## 5. 移动端配合实现

1. **状态管理 (`src/store/useAssistantStore.ts`)**：
   - 服务地址唯一持久化于 AsyncStorage 的 `lvtian-connection-config-v1`；Token 仅通过 `expo-secure-store` 保存。连接配置与 `lvtian-assistant-storage` 聊天缓存分离，不额外保存地址备份、不长期双写；
   - 冷启动独立加载连接配置；仅新记录不存在时从旧聊天记录一次性迁移地址，新记录写入成功后才允许聊天缓存写入，避免初始化状态更新覆盖尚未迁移的来源。新记录已存在（包括明确空地址）时不再读取旧地址；
   - `credentialsStatus` 区分加载中、成功和失败，`credentialsError` 仅存稳定错误码；读取失败保留内存与持久化原值并向调用方抛错，不等同于未配置。配置读取/迁移与保存串行执行，防止旧读取覆盖新配置；
   - `hasHydrated` 表示聊天缓存读取已结束，不代表成功；`chatHydrationError` / `chatCacheError` 分别报告聊天读取/写入失败。读取失败后禁止覆盖原缓存，成功重试 `persist.rehydrate()` 后才恢复写入。任务 HTTP 访问只依赖连接配置就绪；WebSocket 必须等聊天缓存成功读取后再携带正确游标对账，聊天读取失败时不发送或回放消息，避免重试读取旧缓存覆盖新消息；
   - 连接身份切换清除旧会话缓存、游标与离线队列；URL 写入失败时尝试恢复原 SecureStore 令牌，恢复失败单独报错。两个存储介质不构成跨介质断电原子事务，不承诺保存过程中进程被杀的事务性；
   - 维护会话消息队列与当前任务状态。诊断与验证边界见 [连接配置持久化问题记录](问题记录/连接配置持久化问题记录.md)；
2. **长连接客户端 (`src/services/AssistantClient.ts`)**：
   - 单例模式，负责 WebSocket 自动重连（指数退避）、心跳保持、离线恢复；
   - 提供连接测试与剪贴板一键解析能力；
3. **主聊天页面 (`src/screens/ChatScreen.tsx`)**：
   - 连接读取中与聊天缓存读取中显示加载态；配置、令牌及聊天缓存读取失败分别提示并允许显式重试，不显示“未配置”引导，也不开放会被迟到缓存覆盖的聊天输入。缓存写入失败单独显示保存失败并允许重试；
   - 只有连接配置读取成功且确实缺失时才显示未连接引导态（支持一键粘贴配置）；
   - 顶栏连接状态指示；
   - 用户与助理消息流（Markdown 渲染、工具活动状态标签、稳定错误码本地化渲染、`stopReason` 截断提示）；
   - 斜杠命令与技能建议菜单：输入 `/` 即时弹出建议浮层，支持实时检索过滤与补全上屏；输入或发送 `/new` 时触发无感会话重置，屏幕完整保留所有历史记录，仅轻量弹出 Toast 气泡提示；
   - 人工审批卡队列（并发审批逐卡展示、各自同意/拒绝）；
   - 停止执行控制条；
4. **设置页 (`src/screens/AssistantConfigScreen.tsx`)**：
   - 提供服务地址、Token 输入、一键粘贴与即时联通性测试。


## 主聊天工具展示与回底交互

- `ChatScreen.tsx` 经 `src/utils/assistantMessageParts.ts` 按锚点切分正文，但只渲染 `text` 段：工具调用不再进入聊天流，工具之后的新文字另起气泡，纯工具消息不生成空气泡。每次工具调用仍在工作记录里独立展开、默认折叠，展开状态随工具 ID 保持，不因新增调用、正文续写或状态更新而自动展开。任务终态提示仍按整次回复显示。
- 日期按设备本地日历日分隔，置于该日最早可见消息之前（列表数据倒序，比较 `index + 1`），显示今天、昨天、月日或跨年完整日期。加载更早记录后边界重新计算；每分钟及回到前台刷新相对日期，不将“一天”固定视为 24 小时。
- 用户和助手正文气泡内部显示 24 小时时间。`ChatBubbleText` 的可选正文仅包含原文，时钟为独立且不可选的同级节点，不得使用透明时间文字或空格污染复制内容。纯文本首帧由原生 flex row 同时排正文与时钟，正文可收缩，短消息不再经历底部行再跳同行；只有原生行测量确认换行后，才切换到按末行边界、容器宽度及时钟尺寸判断同行的模式。Markdown 富文本（包括空格/Tab 缩进代码和命名/数字实体）通过 `ChatMarkdownBubble` 保留原解析和内联 Text 树；仅当最终可见节点是普通段落或列表末项的 textgroup 时，在该节点自己的满宽 host 内依据原生 `onTextLayout` 末行测量放置时钟，列表缩进由原布局自然保留，不将局部行坐标误作气泡坐标。测量未到、末行空间/高度不足，或以代码块、表格、标题、引用、图片等节点结束时，使用正常布局时间行；不凭字符数估计，不插入隐藏占位。正文/字号及窗口宽度/字体缩放变化使旧测量失效，过期宽度与时间回调不得覆盖新测量；仅时间变化不重挂可选正文。`useLayoutEffect` 仅保护回调版本，不代表异步文本行测量已在首帧绘制前完成。富文本气泡直接作为明确宽度消息组的子节点，自身和 Markdown body 均占满组内可用宽度且不纵向收缩，不得再嵌套到仅 `maxWidth` 的按内容收缩气泡内；不得设置固定高度或裁剪来掩盖列表内容溢出。短纯文本继续使用自适应宽度。排队、发送及出错状态保留可操作的底部状态行。
- **顺序按服务端时间**：消息在时间线上的位置按服务端受理/创建时刻排序，同一毫秒保持服务端到达顺序。`sync_result` 对账只把尚未受理的本地消息按原顺序置于末尾，它们不参与整段排序，避免设备时钟把历史打乱。`seq` 是增量同步游标，流式正文和工具更新都会重写它，不得用于排序；设备时间只用于尚未受理的本地消息。
- **时间只来自服务端**：受理用户消息时 `message_ack` 回传服务端受理时刻，客户端据此覆盖本地设备时间；创建助手消息、任务结束沿用服务端时刻与 `completedAt`。设备时间仅用于尚未受理的本地消息。工具调用沿用 DSH 事件到达服务端的时刻，不单独显示时钟。
- **“正在工作”不是消息**：聊天页不再生成“正在思考中”占位气泡。倒序列表的 `ListHeaderComponent` 承载三点指示，随列表滚动、位于最新消息之下，从任务进入 `processing`/`awaiting_approval` 起持续闪动，直到整轮结束才消失；它不进入消息数据、不参与排序、不计入工作记录。
- **工具调用移出聊天**：聊天页只保留用户消息与助手正文，工具调用统一进入“工作记录”（聊天页右上入口），按“一次用户请求”聚合成一轮：列表给标题、结果摘要与完成时间，详情给该轮工具流水。分段与工具的先后仍由 `toolCallPositions` 锚点决定，剥离只改展示位置；协议只增加助手消息的 `replyTo` 关联，不改变正文与工具数据。
- **工作记录聚合与入口**：`src/utils/chatTurns.ts` 以用户消息 id 作为一轮的身份。助手消息携带 `replyTo`（它实际回答的用户消息 id），排队期间连续收到多条请求时也按该字段归回各自请求；旧历史没有 `replyTo` 时回退到到达顺序。用户消息发送失败或被终止时，该轮直接落为失败态，不永久显示“进行中”；助手回复被停止或审批超时同样按失败终态处理（与服务端保存的 `error` 一致），避免先显示完成、重连后又变未完成。标题取用户请求首个有效行，摘要取助手结论首个有效行，无文字结论时按工具条数本地化兜底。列表按轮次在原会话中的先后倒序、按本地日历日分段，行内显示标题、摘要与 `HH:mm`；运行中的一轮使用开始时间并标注“进行中”，避免把开始时间冒充完成时间。入口固定在聊天页右上，进入本会话的工作记录；选中项按轮次 id 从最新数据派生，运行中也能持续更新。
- **工作记录详情**：详情顶部为关闭与时间，正文依次为短标题、完整请求（与标题不同时展示）、工作过程（工具流水）和结论（完整 Markdown）。列表可以截断标题，详情必须能看到该轮完整交办内容。工具流水与结论都只读展示，不复制、不改写服务端保存的原始输入输出；没有工具或没有文字结论时给出明确空态，不渲染空白区域。
- **工作记录目前是半成品**：这一页没有生成层，只是消息流的投影——标题取用户请求首行、摘要取助手正文首行、结论贴助手正文全文、步骤沿用工具原始标题，因此同一轮内容会在聊天与记录里重复出现。目标形态（对齐 Muse）是在每轮结束时生成一份独立记录：任务标题、一句结果、压缩后的结果说明和可读的步骤描述，随轮持久化，记录页只读这份结果。生成层尚未实现；生成时机、存储归属、失败与重试、额外 token 成本等待后续信息更充分时再讨论。在此之前维持当前投影实现，重复属于已知缺口，不作为当前缺陷处理。
- 服务端 `SessionManager.setToolCall` 保存首次出现位置；现有全消息日志与快照携带锚点，重放增量仅继续追加正文，不重排工具。移动端 `useAssistantStore` 在实时流中生成相同锚点，同步时服务端完整消息覆盖本地记录；已完成消息本地持久化也保留位置。旧历史缺少锚点时沿用工具在前、正文在后的展示，不推测丢失的历史顺序。
- 工作记录详情的工具流水复用 `src/components/ToolCallsCard.tsx`：摘要优先使用结构化 `input`，命令优先显示 `description`，缺省显示命令；文件工具显示操作与目标路径；搜索显示查询。卡片宽度占满详情内容区，不得退回仅 `maxWidth` 的不确定宽度，否则标题的弹性收缩可能将卡片挤成高长条。摘要最多两行并尾部省略，状态独占下一行、箭头保留空间；历史消息及未知工具回退到已有 `summary`/名称。完整参数与原始输出仅在点击展开后渲染；摘要展示不改变服务端保存的原始工具输入输出。
- 图片/文件选择只追加到输入区附件草稿，草稿收纳于输入框胶囊容器内部上方横向排列，以带右上角删除按钮的卡片呈现，支持逐项移除与点击全屏预览；相册选图支持系统原生多选（最多 9 张）与图片预览；聊天气泡中的图片及待发草稿均接入基于 `PanResponder` 的跨平台全屏图片查看器（`ImageViewerModal`），支持单指平移、双击放大/复位与双指捏合缩放（排除对称捏合误退并支持动态落指）。触点切换回单指时须记录当前平移位置与整段手势累计位移，后续仅应用切换后的增量，并清除旧捏合距离，避免跳位及立即再次捏合时沿用旧比例基准。第二指加入时即记录多指状态（不能等到移动），多指操作清除旧点击历史，不参与单击关闭或跨捏合的双击判定。选择、取消或读取失败均不发送、不清空文字。点击发送才将当前文字与全部附件交给现有 `AssistantClient.sendMessage`，无文字时使用已有图片/文件默认说明。草稿附件合计按 20MB 报文预算控制，成功交给客户端后清空输入区；离线或服务升级时仍由既有持久待发队列保存并补发。待发送草稿仅随当前聊天页面保留，不新增未发送草稿落盘机制。排障记录见 [聊天图片交互问题记录.md](问题记录/聊天图片交互问题记录.md)。
- 输入框无文字且无待发送附件、任务执行中时，右侧停止按钮使用 32px 浅蓝色圆形底（主题主色）与 12px 白色方块；有文字或附件时切换为发送箭头，不改变停止指令与排队机制。
- 回到底部按钮只允许主动上翻历史触发：手指拖动累计离开起点超过约 100 个逻辑像素且距底超过 100 时显示，连续短拖保留距离；键盘事件重置手势基准，不触发新按钮，已显示的按钮在仍浏览历史时保留。距底不超过 32 时隐藏，点击按钮立即隐藏并滚回最新消息。惯性及程序滚动本身不会新触发按钮。
