# 服务端架构与通信协议

## 1. 模块定位与职责

绿天（Lvtian）独立服务端位于仓库 `server/` 目录下，负责在用户的 Windows 或 Linux 宿主机（如 VPS 或个人电脑）上常驻运行个人 AI 助理中枢。

### 核心特性
- **Agent-First 架构（以 Agent 为主，宿主机为辅）**：
  - 记忆系统（`SOUL.md`、`MEMORY.md`、`USER.md`、`AGENTS.md`、`memory/`）与专属工作区统一驻留在 `~/workspace/`，透明可读可控，便于作为独立 Git 仓库进行版本管理与多端灾备同步；
  - 隔离系统级根目录与其他无关文件，杜绝全局扫描造成的 Token 膨胀与误触风险；
- **跨平台独立守护运行**：
  - 基于轻量 Node.js（TypeScript），零外部数据库依赖；
  - 提供标准的后台启停脚本（`scripts/start.sh`, `scripts/stop.sh`）、systemd 单元模板（`lvtian-server@.service`）与 Windows 启动脚本（`start.bat`）；
  - 数据与凭据（`~/.config/lvtian/`）与代码及编译产物完全分离；
- **全天候长连接与状态机对账**：
  - 采用标准 WebSocket + HTTP（Bearer Token 鉴权），网络中立，支持局域网、Tailscale 虚拟内网、公网反代域名直连；
  - 手机断网、切后台或锁屏时，服务端底层任务持续执行并不中断；
  - 手机重新连上时，通过 `sync` 报文上报最后接收序号（`lastSeq`），服务端自动补齐离线期间的增量消息与最新执行状态。

## 2. 目录结构与关键代码

```text
server/
├── package.json               # 独立依赖与脚本 (Node >= 22.19.0)
├── tsconfig.json              # 服务端独立编译配置
├── dist/                      # 编译生成产物
├── src/
│   ├── index.ts               # 入口程序：解析参数、优雅停机、打印连接信息
│   ├── config.ts              # 配置管理：端口(3000)、Token生成、工作区解析
│   ├── protocol.ts            # 通信报文与状态契约 (与移动端同构)
│   ├── memoryManager.ts       # 记忆系统：管理 workspace 下 SOUL.md, MEMORY.md, USER.md (AGENTS.md 由引擎原生加载)
│   ├── sessionManager.ts      # 会话中枢：管理序号(seq)、持久化、增量对账
│   ├── dshRunner.ts           # 引擎调度：驱动 dsh 循环、流式解析与中断控制
│   └── server.ts              # 网络中枢：HTTP 健康检查与 WebSocket 长连接管理
└── scripts/
    ├── start.sh               # Linux 后台守护启动脚本
    ├── stop.sh                # Linux 停止脚本
    ├── lvtian-server@.service # systemd 守护单元实例模板 (lvtian-server@<user>.service)
    └── start.bat              # Windows 启动脚本
```

## 3. 通信协议与报文规范

### 3.1 客户端上行报文 (ClientMessage)
- **认证**：`{ type: 'auth', token: string }`
- **对账**：`{ type: 'sync', sessionId: string, lastSeq: number }`
- **发消息**：`{ type: 'chat', sessionId: string, messageId: string, content: string }`
- **人工审批反馈**：`{ type: 'approval_response', approvalId: string, approved: boolean, reason?: string }`
- **停止执行**：`{ type: 'stop', sessionId: string }`
- **心跳**：`{ type: 'ping' }`

### 3.2 服务端下行报文 (ServerMessage)
- **认证结果**：`{ type: 'auth_result', success: boolean, serverInfo?: { version, workspace, assistantName } }`
- **对账结果**：`{ type: 'sync_result', sessionId, messages, taskState, currentSeq }`
- **受理回执**：`{ type: 'message_ack', messageId, seq }`
- **流式事件**：`{ type: 'event_chunk', seq, sessionId, messageId, delta, content?, toolCall, status }`（`content` 用于终态 `final` 全量校准）
- **审批申请**：`{ type: 'approval_request', seq, approvalId, prompt, toolName, params }`
- **状态同步**：`{ type: 'task_status', seq, sessionId, state, error }`
- **心跳回执**：`{ type: 'pong' }`

## 4. 引擎调度与运维安全细节

### 4.1 本地依赖解析与执行隔离
- **本地二进制直调**：服务端通过 `createRequire` 精准定位 `server/node_modules/@deepseek-ai/dsh/lib/bin.js`，以 `process.execPath` 直接调用，杜绝子进程 `cwd` 脱离服务目录时 `npx` 回退联网下载或查找缓存；
- **长文本终态无损保真与多段文本保留**：针对超过 8 KiB 的长文本回答，捕获并消费 dsh 终态 `final` 事件中的完整文本。严格遵循官方 headless 规范，完整保留工具调用前已提交的前置 `text` 文本段，仅使用 `final` 替换终端可能被截断的最后一段，校准 `SessionManager` 持久化副本并通过 `event_chunk` 广播全量文本，防止丢失工具调用前文字或残留截断文本；
- **单轮执行器与审批边界**：当前采用官方 `dsh --profile headless`（单轮一次性执行器），非交互式运行。移动端与报文协议层保持完整的人工审批通用契约，待后续规划独立升级至 ACP (Agent Client Protocol) 交互式长连接通道；
- **进程安全与连接容错**：
  - WebSocket 服务端及连接级均挂载 `error` 监听，防止超限 payload 或非法帧抛出未捕获异常导致守护崩溃；
  - 启停脚本（`start.sh`、`stop.sh`）严格基于 NUL 字符边界逐项全等匹配命令行参数（必须有独立参数全等于 `${SERVER_DIR}/dist/index.js`），自动清理陈旧无效 PID 文件，杜绝仅包含子串或备份文件名导致的误伤。

### 4.2 会话存储：追加式事件日志
- **存储布局**：`sessions/<sessionId>/` 目录承载 `events.jsonl` 活跃日志与 `seg.NNNNNN.jsonl` 轮换封存分段；旧版单文件 `<sessionId>.json` 在服务启动时自动一次性迁移（原文件改名 `.json.migrated` 保留）；
- **追加式写入**：每条状态变更追加一行 JSON 事件（消息新增/整条更新、流式增量、任务状态、dsh 会话绑定、序号推进），写入代价恒定、与历史长度无关，取代旧版「每次变更整文件全量重写」；流式增量内存即时生效、300ms 防抖合并落盘，崩溃窗口由重启修复兜底；
- **快照与轮换**：活跃日志超过 4 MiB（环境变量 `LVTIAN_SESSION_ROTATE_BYTES` 可覆盖，测试用小阈值轻量触发）时轮换——旧日志封存为不可变分段，新日志以全量快照头开始；重启加载只读活跃日志（快照＋其后事件），历史分段无需读入；
- **崩溃自愈**：末行撕裂丢弃、中段损坏停止该文件重放；轮换中途崩溃（活跃日志未落位）时按序重放全部分段恢复；
- **重启修复语义不变**：`processing`/`awaiting_approval` 重置为 `stopped`，流式中断消息标错并推进 seq，修复结果同样以事件追加落盘；
- **内存策略**：消息仍全量驻留内存（聊天消息体积小，真正失控项是写入放大），内存窗口化与加载开窗留给进程常驻化升级一并设计。

## 5. 移动端配合实现

1. **状态管理 (`src/store/useAssistantStore.ts`)**：
   - 存储服务地址与 Token（敏感凭据通过 `expo-secure-store` 加密保存）；
   - 维护会话消息队列与当前任务状态；
2. **长连接客户端 (`src/services/AssistantClient.ts`)**：
   - 单例模式，负责 WebSocket 自动重连（指数退避）、心跳保持、离线恢复；
   - 提供连接测试与剪贴板一键解析能力；
3. **主聊天页面 (`src/screens/ChatScreen.tsx`)**：
   - 未连接引导态（支持一键粘贴配置）；
   - 顶栏连接状态指示；
   - 用户与助理消息流（Markdown 渲染、工具活动状态标签）；
   - 人工审批卡片（同意/拒绝）；
   - 停止执行控制条；
4. **设置页 (`src/screens/AssistantConfigScreen.tsx`)**：
   - 提供服务地址、Token 输入、一键粘贴与即时联通性测试。
