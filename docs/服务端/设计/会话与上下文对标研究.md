# 对标研究：常驻个人助理的会话处理

状态：研究结论文档（不含实现方案）。

研究问题：**常驻个人助理在用户界面上是一条永续对话，在 harness 层面是如何处理这条对话的？**

研究对象（七家，均为 2026-10 前后核实）：

| 层次 | 产品 | 研究深度 |
| --- | --- | --- |
| 开源标杆 | OpenClaw、Hermes Agent | 源码与官方文档级 |
| DSH 同型 | BotHarness/DeepSeekBot、wanpengxie/ash、rlaope/deepseek-bot | 源码与架构决策记录（ADR）级 |
| 闭源行为级 | Meta Muse、OpenAI Dots | 仅公开资料，内部机制未公开处如实标注 |

---

## 一、核心结论

所有常驻个人助理在 UI 层都是一条永续对话，但**没有一家在 harness 层用单个会话原样承载它**。通行做法是两层分离：

1. **UI 层一条线不动**：用户永远看到同一个对话入口，不存在"会话管理"心智负担；
2. **harness 层的会话是消耗品**：或按任务切分（结构分流），或按时间/空闲轮换（生命周期轮换），两者常并用；
3. **膨胀治理分而治之**：模型上下文由引擎压缩兜底；磁盘日志全量放任增长（无害）；每轮恢复成本是唯一无界项，靠切分或轮换封顶；
4. **旧会话全量封存、可查不可写**：没有一家删除历史，连续性靠封存日志的检索能力承担。

一句话：**引擎管会话内部（压缩），产品管会话之间（切分与轮换）**。

---

## 二、永续对话的承载结构（三种形态）

### 形态一：单会话容器

整条对话装在一个长期会话里，膨胀靠轮换治理。

- **OpenClaw**：主会话键 `agent:<agentId>:main`，所有渠道的私信汇聚进这一个会话；群聊、线程、定时任务另行隔离。主会话是系统的根：心跳唤醒它、后台工作向它汇报。
- **Hermes Agent**：每个聊天一个常驻会话，配套 /new、分叉、按名恢复。
- **rlaope/deepseek-bot**：每个频道线程一个 DSH 会话，映射关系（`频道:线程 → 会话ID`）持久化在状态文件中。

### 形态二：主会话 + 任务会话分层

对话与工作分离，各住各的会话。

- **DeepSeekBot**（ADR-0017/0024/0045）：每个 PersonaBot 由一个 **Orchestrator 会话**（装对话与调度，会话 ID 明确设计为稳定不轮换，靠引擎压缩管理上下文，按收件箱批次唤醒而非常驻）加若干 **Assignment 会话**（每条"人类可理解的工作延续线"一个独立根会话，可在专属工作区运行）构成。任务没有独立实体——任务的运行时身份就是 Assignment 会话的 DSH 会话 ID（ADR-0017 明确拒绝再造一套任务账本）。

### 形态三：消息账本

废除"会话"概念本身。

- **ash**：一切进出皆消息，进入一个账本（ledger）；对话界面只是账本的投影。超长字段在写入时即被替换为 blob 引用，账本只存摘要。

---

## 三、膨胀的构成与真问题

单个会话持续增长，分解为三项，性质完全不同：

| 增长项 | 是否有界 | 机制 | 各家态度 |
| --- | --- | --- | --- |
| 模型上下文 | **有界** | 引擎在窗口压力下自动压缩（摘要替换旧历史＋修剪大工具结果），溢出有兜底缩减重试 | 全部依赖引擎；代价是摘要套摘要的质量衰减和压缩时的额外模型调用 |
| 磁盘日志 | 无界但**无害** | 追加式写入、压缩编码、写入代价与历史长度无关 | **七家全部放任**；完整历史永久保留是审计、检索与连续性的共同基础 |
| 每轮恢复成本 | 无界，**唯一真问题** | 每轮开始需装载会话日志恢复状态，耗时随日志长度增加 | 三种治理路线（见下） |

### 恢复成本的三种治理路线

1. **寿命切段**：会话活不长，日志没机会大。DeepSeekBot 按任务切；rlaope 按线程切；
2. **加载开窗**：文件可以大，但每轮只加载有限窗口。OpenClaw 普通对话每轮有历史加载字节上限，压缩边界之前的旧历史留在磁盘上不再加载；
3. **源头瘦身**：让主文件长不快。ash 写入时把超长内容替换为 blob 引用，账本只留摘要。

进程模型决定代价形态：常驻进程把恢复成本摊销到进程生命周期（rlaope 进程内 SDK 驱动、OpenClaw 网关常驻）；每轮拉起的执行器每轮全额支付。**同为 DSH 生态，rlaope（进程内）与绿天当前模式（headless 每轮拉起）即两种形态的对照。**

## 四、切分与轮换：触发机制全景

| 触发方式 | 代表 | 机制 |
| --- | --- | --- |
| 定时 | OpenClaw `mode: "daily"` | 每天指定时刻（默认凌晨 4 点）自动开新会话，旧会话封存 |
| 空闲 | OpenClaw `mode: "idle"`；rlaope `stateRetentionDays: 30` | 静默超时后开新会话。OpenClaw 明确心跳/定时任务等系统事件不算活跃、不给会话续命；rlaope 回收"频道:线程→会话"映射后，线程再被激活自然走新建路径 |
| 任务边界 | OpenClaw cron（每次运行全新会话）；DeepSeekBot Assignment | 会话生来有界，任务即边界 |
| 手动 | OpenClaw / Hermes 的 /new、/reset | 用户主动换新 |

关键细节：

- OpenClaw 支持定时与空闲**双触发，先到期者生效**；触发自动重置的那条消息直接进入新会话继续。重置策略可全局配置，并可按聊天类型、按渠道分别覆盖（如群聊空闲 2 小时、某渠道空闲 7 天）；
- DeepSeekBot 主会话"永不轮换"能成立，靠两个前提：**结构性瘦身**（所有重工作分流到 Assignment，主会话只装聊天与调度，长得极慢）＋**接受每批唤醒的恢复成本**（它非常驻，按收件箱批次唤醒）。永续可行性是靠控制内容增长换来的，不是靠消灭启动成本。

### 规则路由 vs 模型判断路由

任务分到哪个会话，由谁决定——两种路线：

- **规则路由（按消息来源）**：OpenClaw 的会话路由是确定性策略表——私信进主会话、群聊按群隔离、cron 每次新会话、Webhook 每钩子一会话。不经模型判断，零判断成本、零误判；
- **模型判断路由**：DeepSeekBot 的派发全部由 Orchestrator 判断（直接答还是开 Assignment、复用哪个）。灵活，但每次派发消耗模型调用，判断失误工作会漏进主会话或进错任务。

可靠性结论：**能被规则表达的边界（定时任务、产品结构中已存在的任务实体）用规则；模型判断只留给"用户随口一句话引出的临时工作"这类灰色地带。** 全判断制（DeepAgent 式）把所有边界交给模型，是效率与可靠性的双重代价。

### 多 Agent 协作的效率工程（DeepSeekBot，ADR-0045/0059）

任务分流必然带来跨会话通信，其成本控制有成熟图纸：

- 创建任务**非阻塞**：登记即返回，主 Agent 本轮不被挂起；
- 汇报是**指针不是载荷**：回传会话 ID＋因果标记＋产物引用，超长内容溢写，主 Agent 按需下钻；未被查看的重复汇报合并为一条（最新摘要＋重复计数，最多唤醒一次）；普通进展默认进摘要批次不打断；
- 主 Agent 不靠上下文记忆手下任务（压缩会丢），靠**持久化任务目录**查询——"X 进展如何"经常查目录直接回答，任务会话不唤醒；
- 并发上限（默认 3）满则结构化拒绝，不排虚拟队列；
- 请求分语义模式：补上下文（不唤醒）、调方向（下个安全边界生效）、追加下一轮；不打断执行中的步骤。

## 五、旧会话的封存与可查性

被切分和轮换掉的旧会话，各家归宿一致：**全量封存、可查、不可写**。

- **DSH 生态**（rlaope、DeepSeekBot、绿天）：会话日志即封存形态。DSH 提供 sessionQuery 查询服务；DeepSeekBot 明确已完成/已取消的任务保留可查、不按时间自动删除，永久删除是显式操作；
- **rlaope 的检索索引**：主机侧运行索引器，把 DSH 压缩会话日志解开建成可检索的纯文本索引放进 Agent 工作区，Agent 用普通文件工具即可"回忆"过去的会话（实测 61 个会话日志索引约 0.4 秒）。这是"换会话后不失忆"在会话层的直接答案；
- **OpenClaw**：完整历史永久在磁盘，会话检索（sessions_search）全量可查，压缩只改变模型所见；
- **ash**：账本本身就是全量记录，投影按需读取。

## 六、DSH 引擎的能力边界

对照上述机制，DSH 引擎（v0.2.1-rc 系）提供与不提供的：

**引擎提供（绿天可直接使用）**：

- 单会话内部：自动压缩（默认开启，窗口 80% 阈值触发，先修剪大工具结果再摘要替换，溢出自动缩减重试）；
- 持久化：单文件追加式日志（zstd 压缩帧、崩溃自愈、大日志流式恢复管线、格式版本迁移），每会话独立目录；
- 会话间原语：子代理（spawn/resume/followup/steer/inject）、sessionQuery 查询、进程内 SDK 与 ACP 两种驱动方式（rlaope 用 SDK，ash 用 ACP，均已验证可行）。

**引擎不提供（属于产品层职责）**：

- 会话轮换策略（定时/空闲/任务边界触发）；
- 按消息来源或任务结构的会话路由；
- 加载开窗（每轮历史加载上限是 harness 自身的权力，DSH 无此配置）;
- 跨会话的消息纪律工程（汇报指针化、合并、目录查询等）。

## 附录：产品档案卡

### OpenClaw（开源，★392k）
- 定位：自托管个人 Agent；主会话单容器形态＋可选子代理（会话孵化树、跨 Agent 消息 sessions_send、可见范围四档权限、子代理并发/超时配置）。
- 会话要点：主会话 ID 默认长期稳定（`mode:"none"`）＋可选每日/空闲自动重置（双触发先到先换，按类型/渠道覆盖）；每轮历史加载有界；cron 每次新会话；压缩＝摘要替换＋工具结果修剪。
- 证据：官方文档 docs/concepts/{session,main-session,compaction,session-pruning}.md、docs/gateway/config-tools/sessions-and-subagents.md。

### Hermes Agent（开源，Nous Research）
- 定位：多平台网关型 Agent 框架。
- 会话要点：每聊天一常驻会话；SQLite（FTS5 全文检索）＋JSONL 转录双存储；自动上下文压缩＋手动 /compress（可保留最近 N 轮、可预览）；/new、分叉、按名恢复。
- 证据：官方技能文档 slash-commands 参考、运行实例。

### BotHarness/DeepSeekBot（开源，★255，2026-09 创建，持续活跃）
- 定位：DSH 之上 的个人 Bot 团队产品（多 PersonaBot）。
- 会话要点：Orchestrator 会话（稳定 ID 永不轮换）＋Assignment 会话（任务即会话，独立根会话＋专属工作区）；持久化任务目录；消息纪律工程（指针化汇报、合并、摘要批次）；并发上限默认 3；记忆为每 Bot 一个 Git 仓库（演化即提交，可 diff 可回滚）。
- 证据：仓库 docs/adr/0017、0024、0045、0059；verify-deepseekbot 特性文档。

### wanpengxie/ash（开源，★7，2026-09 创建，活跃）
- 定位：Android 常驻个人 Agent，DSH 原包经 ACP 驱动、MCP 调中枢工具。
- 会话要点：消息账本形态，废除会话概念；长内容写入时 blob 化，账本只留摘要；记忆为 Markdown 文件，逐条修改＋冲突检测。
- 证据：仓库 README、packages/sdk/src/conversation.ts、AshMemoryWriter.kt。

### rlaope/deepseek-bot（开源，★76，2026-10 创建，活跃）
- 定位：DSH 引擎的 always-on 个人队友（Slack/Discord/Telegram）。
- 会话要点：每频道线程一个 DSH 会话（进程内 SDK 驱动）；30 天静默回收会话映射、再激活自然开新会话；主机侧会话日志检索索引供回忆。
- 证据：仓库 index.ts、recall/deepbot-recall.ts、docs/how-it-works.md。

### Meta Muse（闭源，2026-09-08 发布）
- 定位：Secure VM 常驻个人 Agent，UI 为单一持久对话线程。
- 会话要点：跨对话连续性靠模型级 Active Memory（Muse Wonder：跨对话携带上下文＋按任务主动检索）；harness 层会话处理未公开。
- 证据强度：官方发布与模型研究博客；内部机制不猜测。

### OpenAI Dots（闭源，2026-09-29 DevDay 发布）
- 定位：ChatGPT 内 always-on 个人 Agent，每 dot 独立云电脑＋浏览器＋记忆。
- 会话要点：persistent reasoning（记住既往交互与任务结果）；平台侧上下文接近上限时自动压缩（二手信源）。
- 证据强度：官方发布与多家权威报道；内部机制不猜测。
