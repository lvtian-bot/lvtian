# 后台作业主动回复未进入主聊天

## 结论与验证范围

普通 ACP `session/update` 只关联活跃请求。后台 Bash 作业结束后，DeepSeek Harness 可以自动发起一次模型执行，这次执行没有用户 ACP 请求，因此原先虽已生成正文，绿天也不会写入主聊天。

修复在同一个 ACP 子进程挂载项目 observer，从 DSH 的 inbox 与 session 事件识别仅由 `tool-jobs` 完成通知唤起的执行。只在执行成功结束时交付最终助手正文。服务端核对当前上游会话绑定，以稳定消息 ID 去重，先持久化，再走既有聊天对账。结果带明确的后台来源，App 仅在主聊天显示，不归入工作记录；如已有预生成接力提要，连同完整结果持久化。相同执行若同时含用户输入，仍走用户回复通道，不额外发一条。跨管道乱序时按 ACP 消息和工具 ID 对齐，不把自主回复串入用户正常请求。

本地用实际 DSH 后台 job 及合成模型验证唤起；用独立的真实 ACP 子进程验证写入绿天聊天并从磁盘重读，未部署生产。修复不追补旧版本已经丢失的报告，不改变绿天原生定时任务、技能或现有工具权限。

## 复现记录（2026-11-21）

- PR 跟踪 Bash 作业在 17:44:00 退出，DSH 在同一时刻记录完成通知及新的模型执行，17:44:13 生成最终汇报。绿天主聊天在用户追问前未保存此回复。
- 正常用户执行结束会移除该次 ACP 回复所需状态；仅删除空状态保护不能区分后续的历史重放、普通回复和后台回复，因此通过 DSH 原始事件建立明确的回复来源及终态边界。
