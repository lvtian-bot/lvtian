## 2026-10-27 本地排查

### 文本附件转义低估

- 触发：选取两份各 8MiB、包含大量制表符或反斜杠的文本，再发送。
- 根因：`ChatScreen.appendPendingAttachments` 以文件字节数乘 1.2 估算文本编码大小；JSON 转义可能使字符变为 2 至 6 字节，不能用固定 20% 余量保证预算。
- 验证：两份制表符文本估算 19.200001MiB，通过 20MiB 草稿预算，但实际 JSON 为 32.000213MiB，超过服务端 30MiB 上限。独立回环 WebSocket 验证也确认超限报文导致连接关闭。
- 修复：以小型共享工具 `src/utils/attachmentBudget.ts` 计算序列化附件数组的真实 UTF-8 字节数，覆盖 JSON 转义、多字节文本、Base64 与元数据；草稿、发送及重新读取后的重试/离线补发统一沿用 20MiB 预算。URI-only 图片先读取实际数据再计费，失败重试超限时不删除原失败记录。额度及可见文案不变，不增加独立正文限额。
- 当前状态：实现及回归已完成；附件草稿、字节工具、客户端补发、既有客户端队列和图片入口合计 5 套件 54 项通过，类型检查、限定文件 ESLint 和差异检查通过。覆盖转义文本、中文/代理对、合计图片、单文件、URI-only 图片读取、重试及离线补发，超限保留草稿/失败记录且后续队列可推进；主分支集成后的全量结果另补。

### 旧报文上限测试超时并挂住

- 触发：执行 `server/npm test`。
- 根因：`server/test/server.test.mjs` 的连接错误测试仍发送 `5MiB + 1KiB` 并期待超过上限断连，而本 PR 将服务端上限改为 30MiB。断言在 5 秒后超时，失败路径未关闭测试服务和连接，导致测试进程不能正常结束。
- 验证：本地复现明确失败 `超大报文未在预期时间内触发连接关闭`；其余已输出测试通过，挂起任务由人工取消，不能计为全量通过。云端 run `40422807720` 的同一测试步骤运行约 15 分钟后被取消，现象与本地一致，尚不将云端取消操作本身的原因作确定判断。
- 修复：测试报文改为 `30MiB + 1KiB`，验证关闭码 1009；通过测试清理钩子关闭客户端、服务端连接及服务器，取消超时定时器，保证断言失败也释放资源。正常连接检查等待真实关闭；单测设置 15 秒上限。
- 当前状态：定向测试及构建通过；集成主分支前完整服务端 169 项测试全部通过，进程正常结束（约 21 秒），不再挂起。集成后仍须重跑完整验证。

### 多指操作与点击状态边界

以下两项已本地修复：在触点开始事件中记录静止多指操作，并在多指开始及移动入口清除旧点击历史。新增 8 项正式真实 responder 回归；查看器共 17 项，与原图片入口合计 22 项定向测试通过，类型检查及限定文件 ESLint 通过。修前新回归实跑 7 项失败，修后通过；真机仍待验收。

1. 第一根手指落下后加入第二根，再依次抬起，两指均未移动：原实现没有 `onPanResponderStart` 记录第二指加入，最终按单击判定，280ms 后意外关闭。现于触点加入时记录多指状态，任一手指先抬或同时抬均不参与单击关闭。
2. 单击后 50ms 做触点中心不动的对称捏合，将比例从 1 放到 1.5；再过 50ms 单击：原实现没有清除上次点击记录，该次单击被当成双击，比例意外复位为 1。现于多指操作入口清除双击历史，单击保持 1.5，之后真正连续的纯单指双击仍正常放大/复位。
