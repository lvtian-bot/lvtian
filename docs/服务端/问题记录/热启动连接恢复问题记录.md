# 热启动连接恢复问题记录

- 2026-11-06 已实现连接阶段超时、网络变化恢复、前台陈旧连接替换、旧 Socket 回调隔离与耗时日志；沿用现有 WebSocket 协议与对账游标。
- 自动化覆盖握手/认证/对账超时、前后台切换、Wi-Fi/移动网络切换、断网恢复、局域网可达性、显式断开/认证失败、离线消息回执和异步附件补发。
- 本机没有连接 Android 真机；尚未验证用户报告的慢连接能否复现，也未获得优化前后的手机耗时数据，不能声称已解决所有慢连接或达到固定连接速度。
- 待发布后真机验收；更换增量同步游标需独立核对缓存与服务端消息完整性，本次未实施。当前连接约束见 [服务端架构与通信协议](../服务端架构与协议.md)。

## 2026-11-06 调查与实现

### 用户现象与源码证据

- 用户反馈 App 从后台回到前台时偶尔连接偏慢；没有给出单次持续时长和网络类型，发生频率未知。
- 原前台处理遇到 `CONNECTING` 直接返回，未设置应用层握手期限；这条路径可能长期等待原生网络栈，尚未证实它就是用户实际遇到的原因。
- 原长连接没有网络变化监听；网络恢复依赖关闭事件、重试或心跳。打开 Socket 即设为 `connected`，未等待认证与聊天对账。
- 原短暂停留探活最长等待 3.5 秒后再重连；后台超过 3 秒则重建连接。文档中的“0-RTT”不能代表实际网络耗时，本次改为准确说明。
- 前次只读探测确认当时服务运行、健康检查及公网域名 WebSocket 握手成功；探测在服务器发起，不能替代手机网络验证。

### 采用方案

- 握手/认证/对账分别设置 8/8/20 秒期限。回到前台时，等待中的阶段已满 3 秒则替换，刚发起的阶段继续等待；已有健康连接的短暂切后台仍使用探活。
- 网络明确断开时暂停重试；恢复或切换时合并事件并主动重连。公网校验失败不能直接否定局域网/VPN 连接。
- 对账应用完成后才设为可用，再补发排队消息；异步附件读取结束后再次核对 Socket 身份和可用状态。
- 清理旧连接时同时清理全部连接计时器；回调、超时及凭据加载迟到结果不能重启或修改已替换/显式关闭的连接。
- 固定字段记录各阶段时间，不输出配置、令牌、聊天内容；连接耗时仍受手机信号、DNS、TLS 及服务可达性影响。

### 验证过程

- 第一轮定向测试中，原初始化及排队测试通过；新增测试的 AppState 初始值及凭据返回值模拟存在问题，已修正。
- 完整回归首次执行时，原任务页面一项测试超过默认 5 秒；当时同时运行类型与 Lint 检查，尚不能将超时归因于资源竞争。另发现直接调用消息处理的测试没有真实 Socket 时启动了心跳，已增加只有打开 Socket 才启动心跳的保护，并重新回归。

- 最终功能回归 35 个测试文件、362 项测试全部通过；TypeScript 通过，ESLint 无错误，只有 3 条原有服务端警告。串行重跑时原任务页面测试通过。`--detectOpenHandles` 再次确认全部通过，残留的 3 个句柄来自原有模型/权限切换 HTTP 失败路径的 60 秒超时计时器，不是本次新增连接计时器；本次不扩大修改远程设置请求。
- 新增连接就绪门禁后，原有三个队列测试补齐 `connected` 前置条件，以确保仍真实覆盖错误回执推进及附件失败/清空路径。

### 真机验收

1. 相同网络下切后台 1 秒、5 秒、1 分钟后打开聊天，观察恢复时间和消息完整性。
2. Wi-Fi 与移动网络互切、飞行模式开关、无网打开后恢复，确认自动恢复且不持续空转重试。
3. 恢复期间发送文字及附件，确认本地保留，恢复后自动补发，回执后出队且服务端不重复执行。
4. 认证错误时保留错误，修正配置后可重新连接；局域网或 VPN 服务在公网校验失败时仍可尝试。
5. 如仍慢，收集同次连接的阶段日志，区分握手、认证、对账接收和消息应用耗时。
