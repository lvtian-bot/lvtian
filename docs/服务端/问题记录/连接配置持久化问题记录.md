# 连接配置持久化问题记录

## 当前结论与边界

- 2026-11-03 用户确认不迁移旧混存记录；聊天缓存可丢弃并不阻断连接，待发送队列按身份独立保存，读取失败即放弃未读出的队列，写入失败时内存消息可能丢失。缓存失败时服务端最近 100 条可恢复，旧混存记录启动时直接清理，旧本地未发送消息不迁移。尚需 Android 真机验收。

- 已确认代码缺陷：连接地址与聊天缓存混存在同一条 AsyncStorage 记录；安全存储读取异常被原实现转为空令牌；聊天缓存读取失败未结束初始化，任务 HTTP 访问又依赖聊天加载标志。
- 尚未证明：上述缺陷就是用户手机本次热更新后配置丢失的完整因果链。没有该次手机日志或真机复现，不断言 OTA 清除了地址或令牌。
- 修正方向：连接地址独立且只有一个有效持久化来源，令牌继续使用 SecureStore；读失败、确实缺失和聊天缓存失败分开处理，不加地址副本恢复机制。
- 三条连接配置、令牌与聊天缓存读取失败提示已获确认；真机 OTA、系统安全存储异常和进程被杀场景尚未验收。

## 2026-10-29：替换地址备份方案

### 原方案及问题

原 PR #50 在 `lvtian-assistant-storage` 之外增加地址备份，在主记录读取失败后恢复地址。它没有消除地址和聊天缓存的耦合，还增加了双写及副本选取责任，因而不作为当前解决方向。

### 当前实现

1. `connectionConfig.ts` 使用 `lvtian-connection-config-v1` 唯一保存地址，SecureStore 原键只保存令牌。旧备份模块退出运行链路，不读取旧备份键；不擅自清理历史残留键。
2. 新配置记录不存在时才读取旧聊天记录迁移地址；先提交新记录，再允许写入聊天缓存。新记录读取失败、格式无效、迁移失败都抛稳定错误码，不当作空配置。
3. 连接读写串行；加载失败不覆盖内存地址/令牌，也不清除存储内容。普通页面聚焦不进入凭据自动重试循环，显式重试可重新读取。用户明确保存新配置时直接写入新记录，不依赖损坏的旧配置/聊天记录读取成功；未知旧身份按切换身份清空内存会话，旧记录在新配置保存成功前不被覆盖。
4. 聊天缓存仅合并和序列化所属字段；聊天读取结束与成功分开记录。读取失败后禁止改写原缓存，成功重新读取后才能恢复写入，写入失败单独报告。
5. 任务 HTTP 访问只依赖独立连接就绪；WebSocket 对账等待聊天缓存成功读取以取得游标。聊天读取失败时页面明确报错并暂停聊天发送与回放，成功重试后才连接，避免重读旧缓存覆盖已回放的新消息或新离线队列。迟到的旧身份缓存不能覆盖用户新保存的身份和聊天；永久损坏不自动删除或绕过，需另行明确处置。
6. 保存跨越 SecureStore 和 AsyncStorage，不能提供跨介质断电事务保证。运行时地址写入失败尝试恢复原令牌，恢复失败单独报告；不以吞异常或伪造保存成功掩盖不一致。
