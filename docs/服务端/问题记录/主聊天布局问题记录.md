# 主聊天布局问题记录

## 当前结论与验证边界

- 2026-11-04 已按确认方案保留末行自适应，不预留固定时钟列：静态消息在真实挂载树中先测量、确定时钟同行或底部位置后整行显现；流式正文立即显示，任务生成期间不显示时钟，终态再定位。另修正发送中/排队/失败到确认状态切换时的 footer→正文时钟路径。当前为代码与模拟回调验证，尚未发布，不能宣称 Android 首帧已经真机验收。

- 富文本气泡继续占满明确宽度的消息组；最终普通段落/列表末项复用 `ChatBubbleText`，按真实原生末行边界决定同行时钟，代码/表格/标题/引用/图片等结尾安全回退到底部时间行。时钟始终是可选正文之外的独立节点，不污染复制。
- 短纯文本保留原生 flex row，原生确认多行后转完整宽度测量。`ChatBubbleReveal` 在测量期间隐藏整条消息行（包括气泡背景），保留横向约束、暂不占列表高度；不是只隐藏时间。测量遗漏的 750ms 安全截止会锁定正常流 footer 并显示消息，之后迟到回调不再移动时间。已显示的 footer 在仅时间更新的测量期间保留几何，避免先收缩再撑开。
- 已添加真实 Markdown 解析/组件树回归，覆盖列表、粗体、行内代码、代码块、表格、字号及流式更新；聊天单元集成测试检查不存在额外的按内容收缩气泡父层。
- ReactTestRenderer 不执行原生 Yoga 测量。当前环境没有 adb 或 Android 真机/模拟器，截图对应的实际宽度、高度、系统大字体及键盘行为仍待真机验收，不能将组件树断言当成原生视觉验收。

## 2026-11-04：确认后实施与验证

- 用户否决固定预留时钟列，确认“先算完再显示”的方向；Markdown 以不影响聊天为前提，必要时简化。
- 追加定位：用户发送中/排队/失败时原来单独显示底部时钟，确认后才挂载 `ChatBubbleText`；这一路径即使末行测量正确，也会产生可见搬动。现在有正文的用户消息始终复用同一正文/时钟组件，状态操作仍在独立底部行，不重复时间，确认不再重挂可选正文。
- 新增 `ChatBubbleReveal`：复用真实正文树，不复制文本做隐藏测量。静态消息初次测量期间将整行设为零高、透明且禁止交互/无障碍访问，横向约束不变、交叉轴不拉伸；各正文的测量都就绪才恢复正常消息行。无测量组件的附件/复杂结尾直接显示；窗口/系统字体缩放/字号变化重建门禁。若 750ms 未完成，锁定正常 footer 后显示，不让消息永久消失，不把迟到结果再挪成同行。
- 流式消息绕过整行门禁，正文立即显示；时间生成期间保持隐藏且不占 footer 行，终态才显示最终位置，避免每个 token 反复显隐。曾经流式显示的纯文本保留完整正文宽度模式，不在结束时重回 row、挤窄单行并重挂正文。已完成消息的时间变化只重测时钟，不重挂正文；保留上次已确认的 footer/inline 几何，避免新时钟测量期间气泡先缩再长。
- Markdown 仍为原生 Text/View：h1–h6、列表间距、引用竖线、代码浅底细边、表头/表格边框和链接色向文件预览靠齐；复用已安装解析器的 `html:false`、`breaks/linkify/typographer:true`。不加入 WebView、额外滚动宿主或依赖，不改原文消息为 Markdown；代码原文继续可选择。网页高亮/复制按钮/任务框/FrontMatter/宽表横滚不照搬，宽表正常流换行，不承诺像素一致。
- 本地 App 35 套件 346 项、服务端 212 项、客户端/服务端类型检查、全仓 Lint（零错误，3 条既有服务端警告）和 diff 检查通过。服务端首次运行因任务树缺少依赖失败，核对与主分支锁文件一致后复用主树既有依赖重跑通过，未安装依赖或修改服务端代码。使用 `NODE_ENV=test`，全量 Jest 采用 `--forceExit`，未退出句柄不作为本次已修问题。新增回归覆盖整行隐藏、短行/多行、footer、迟到回调、多气泡等待、流式不中断、跨分钟 footer 占位、无回调安全截止及发送状态切换。
- 验收缺口：本机未发现 adb，无 Android 真机/模拟器录屏。须实测零高隐藏测量的 Fabric 回调是否完整、常态等待时长、长消息首次列表插入/滚动、Android 大字体/旋转/键盘、复制及流式终态。不把人工回调测试当 Yoga 布局或零帧跳动证明。

## 2026-11-04：时间戳跳动回访与系统排查（历史提案，已被上方确认方案替代）

- `ChatBubbleText` 初始 `multiline=false`，纯文本走原生 row；原生回报多行后切换非 row，而全宽 `body` 尚无有效测量，故先显示 footer。下一次正文/时钟测量齐备才改绝对定位。Markdown 的 `fullWidth` 模式从首帧就处于非 row，也会经历 footer→同行。正文、时间、窗口或字号使测量失效时可重走该路径。
- 既有 RN 原生实现 `ParagraphShadowNode.cpp` 在 layout 中 measureLines，通过 `ParagraphEventEmitter.cpp` 的 textLayout 事件进入 `EventDispatcher` 队列；JS 的 setState 是后续提交。`useLayoutEffect` 不能令异步末行测量变成首帧前同步排版。
- 无新增依赖的推荐方案：始终原生 row，正文为独立时钟预留一列、底部对齐，复制正文不含时钟；代价是多行略早换行，Markdown 末段/末列表项相应留列。替代方案为始终底部时间行，保持正文换行但取消同行效果。严格保留现有末行最优填充且要求原子首帧，需要单独评估原生排版宿主，不能通过隐藏时钟或透明字符伪装修复。
- 现有部分测试 JSX 属性 `text="first\\nlast"` 是字面反斜线而不是真换行，后续应改成表达式字符串并补覆盖；合成 onTextLayout 回调仍不能替代真机验收。当前没有原生首帧录屏或复制实测证据，本次仅分析、未修改时间戳代码或宣称修复。

## 2026-11-04：聊天 Markdown 与文件预览一致性评估（历史评估，轻量实现见上方）

- 用户希望聊天 Markdown 与文件预览保持一致。当前聊天 `ChatMarkdownBubble` 使用 `react-native-markdown-display` 的原生 Text/View；`preview-web` 使用 markdown-it、GitHub CSS 与 highlight.js，在 `PreviewScreen` 的单 WebView 内展示。两处不是同一渲染宿主，直接共用 CSS 不可行。
- 预览显式启用 breaks/linkify/typographer，另有只读任务列表、FrontMatter、代码语言栏/高亮及宽表格滚动；聊天未配置同套扩展，标题比例、段落留白、代码和表格样式也不同。预览的复制桥现状不能当成已有可靠原生兜底，需单独验证成功反馈。
- 推荐统一常用语法清单和视觉 tokens，由原生和 CSS 分别适配，保留流式聊天、工具锚点切分气泡及正文选择复制。不擅自把用户原文消息也转 Markdown，不合并工具前后文本，不自动赋予聊天文件预览的相对路径解析或本地文件权限。精确像素一致则需独立评估共用 Web 核心、流式高度/选区/虚拟列表和资源隔离，不能逐气泡直接嵌入完整 PreviewScreen。
- 已向用户提议“Markdown 风格向文件预览对齐”，等待确认。验收需同一夹具覆盖标题、嵌套列表、引用、代码、宽表格、任务框、实体、链接/图片和恶意 HTML；另验收流式未闭合围栏、三档字体、长文滚动与干净复制。当前无渲染修改、无真机像素一致性结论。

## 2026-10-29：富文本末行仍独占时间行、短消息时间先换行再跳回

### 根因与处理

- 之前 `ChatMarkdownBubble` 无条件在全文之后渲染 footer，因此截图最后一个列表项即使有空位也不能共享时间。现在沿真实 AST 的末子节点链，只接受 body/paragraph/list/list_item 通往 textgroup 的结尾；保持原粗体、链接、行内代码、嵌套列表和选择树，不拆 Markdown 为字符串。
- 末段测量 host 与正文 Text 共用局部坐标，时钟就在该 host 右侧定位，天然计入列表符号与嵌套缩进。必须同时满足末行右边界 + 8px 间隔 + 实测时钟宽度不超 host、时钟高度不超行高，否则正常 footer；图片、表格、代码等不参与猜测。
- 原纯文本先渲染 footer，再经多个异步布局事件改成绝对定位，导致短新消息可见跳动。改为首帧原生 row，时钟保留自己的宽度，正文 flexShrink；原生确认多行后才转完整正文宽度测量。单行不等待 JS 测量来决定同行，也不再手算气泡宽度/物理像素舍入。
- 正文/字号/窗口宽度/fontScale 改变隔离旧测量；宽度与时间更新后的过期回调不能覆盖有效结果。只更新时间不重挂可选正文。

### 验证范围与剩余验收

- `ChatMarkdownBubble.test.tsx` 使用真实解析，新增截图同类末项“真机验证仍未完成，可重启 App 检查更新后的行为。”、普通末段、嵌套列表、局部非零 x 边界、不支持结尾 footer、无时间工作记录；`ChatBubbleLayout.test.tsx` 检查首帧 row 及单行测量后几何样式不变、多行宽高回退、改宽/改时/改正文/字号的迟到回调。
- RN 当前公开宿主同步矩形测量只能提供盒子，不能提供排版后的末行边界；`useLayoutEffect` 本身不能把异步 `onTextLayout` 变成 prepaint 文本测量。因此未引入宿主私有 API、依赖、虚假字符几何或透明占位。多行与富文本首次测量仍可能从安全 footer 转同行；本次短消息通过原生 row 消除该路径，不宣称所有布局零帧变化。
- 本地专项 `NODE_ENV=test npx jest --runInBand ChatBubbleLayout ChatMarkdownBubble`：2 个套件、30 项通过。图片结尾只替换 FitImage 远程尺寸组件（Expo 的 Image.getSize mock 不支持其 Promise 用法），Markdown 解析与图片 AST 规则仍真实执行。
- 最终本地全量：客户端 33 个套件、348 项测试通过；客户端与服务端类型检查通过，服务端 212 项测试通过；全仓 Lint 无错误，仅保留 3 条既有服务端警告，`git diff --check` 通过。
- 本地 Jest 必须显式 `NODE_ENV=test`（环境默认 production，直接运行使 ReactTestRenderer.act 不可用）。测试仅注入代表性的原生回调数据，**不是设备上实际测到的行或首帧录屏**。
- 待 Android 真机：新发短中文/英文/emoji 消息首帧、截图长列表最后一项、窄屏旋转前后、系统大字体与字体缩放、长 URL/显式换行、流式新增段落、复制末段无时间或填充。现有环境无 adb/模拟器，尚未完成原生视觉验收。

## 2026-10-26：列表回复气泡过窄、正文越界及时间重叠

### 现象

主聊天里，含项目符号列表、粗体和行内代码的助手回复，气泡只占左侧较窄区域，右侧空白明显；长列表文字越过气泡底部，时间与正文重叠。截图上相邻用户消息与普通助手文字气泡无同样的窄列现象。

### 代码证据

- 助手消息组已明确为可用区域的 92%，但原富文本仍嵌套在 `alignSelf: flex-start`、只有 `maxWidth: 100%` 的按内容收缩气泡内。
- `react-native-markdown-display` 默认段落使用百分比宽度，列表内容使用弹性布局；原 Markdown body 没有确定宽度。在按内容收缩父层里，百分比段落和弹性列表缺少稳定的测量宽度约束。
- 原时间虽已在正常布局中，但正文测量异常时仍可能在视觉上与越界内容重叠；不能通过隐藏越界内容或固定气泡高度解决。

### 处理

- 将现有 Markdown 选择复制规则和动态字号样式迁入 `src/components/ChatMarkdownBubble.tsx`，不更换渲染器、不增加依赖。
- 富文本气泡直接放在明确宽度的消息组下，气泡和 Markdown body 均设置 `width: 100%`、`flexShrink: 0`，不设置固定高度或内容裁剪。
- 时钟作为 Markdown 之后独立且不可选的同级节点，不向正文添加时间或隐藏占位字符。
- 纯文本、工具分组、任务停止、队列以及服务端协议不变。

### 验证与后续

- 专项测试：`ChatMarkdownBubble.test.tsx` 使用真实 Markdown 解析，覆盖嵌套列表与格式继承、三档字号、代码复制、表格和流式新增末段。
- 集成测试：`ChatBubbleLayout.test.tsx` 使用截图同类列表内容，检查富文本直接挂在 92% 宽的消息组内；原纯文本、日期与工具分组回归继续保留。
- 真机验收：复查截图同类中文列表长回复、系统大字体、旋转或窄屏情况下的宽高与末尾时间，确认正文完整且没有覆盖。
