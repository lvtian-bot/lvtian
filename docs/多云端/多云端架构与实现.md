# 多云端架构与实现

> 本文档说明 MDNote 多云端接入架构设计、策略模式应用、腾讯云 COS 与 WebDAV 的具体实现细节。

---

## 1. 架构设计与接口契约

MDNote 采用**策略模式 (Strategy Pattern)** 解耦具体云厂商协议，对外暴露统一的 `CloudService` 门面：

```text
               ┌───────────────────────┐
               │     CloudService      │
               └───────────┬───────────┘
                           │ 调度与门面
                           ▼
               ┌───────────────────────┐
               │    ICloudProvider     │
               └───────────┬───────────┘
                           │
             ┌─────────────┴─────────────┐
             ▼                           ▼
┌─────────────────────────┐ ┌─────────────────────────┐
│   TencentCOSProvider    │ │     WebDavProvider      │
│  (腾讯云对象存储 REST)   │ │  (RFC 4918 标准协议)  │
└─────────────────────────┘ └─────────────────────────┘
```

### 1.1 `ICloudProvider` 标准接口
```typescript
export interface CloudFile {
  name: string;
  path: string;
  size: number;
  lastModified: Date;
  etag: string;
  isDirectory: boolean;
}

export interface ICloudProvider {
  name: string;
  isConfigured(): Promise<boolean>;
  listFiles(prefix?: string): Promise<CloudFile[]>;
  uploadFile(path: string, content: string, options?: { ifMatch?: string }): Promise<{ etag: string }>;
  downloadFile(path: string): Promise<string>;
  deleteFile(path: string): Promise<void>;
  headFile(path: string): Promise<{ etag: string; lastModified: Date } | null>;
}
```

## 2. 核心 Provider 实现

### 2.1 腾讯云 COS (TencentCOSProvider)
- **底层通信**：使用 REST API 交互，无需依赖体积庞大的官方 Node SDK，极大减轻移动端体积。
- **签名机制**：由 `src/utils/cosSignature.ts` 提供 HMAC-SHA1 签名运算，安全校验请求时间戳与凭据。
- **并发控制**：在上传时传入 `If-Match: etag` 请求头，天然支持服务端乐观锁。

### 2.2 WebDAV 协议 (WebDavProvider)
- **标准方法映射**：
  - `PROPFIND` (Depth: 1)：获取指定目录下的文件元数据与 ETag 列表。
  - `PUT`：上传文件内容，携带 `If-Match` 头防止覆盖。
  - `GET`：拉取文件正文。
  - `MKCOL`：递归保证远端父级目录结构存在。
- **多端兼容性**：支持坚果云 (Jianguoyun)、Nextcloud、自建 Synology/NAS 等标准服务。

## 3. 初始化与 Hydration 约束

- `CloudService` 必须根据 `useSettingsStore` 中选定的存储服务类型动态实例化具体的 Provider。
- **启动铁律**：由于凭据保存在本地存储与 SecureStore 中，在调用 `cloudService.initProvider()` 前，**必须确保 Store 已完成 Hydration（即 `hasHydrated === true`）**，避免因读取空配置导致误判为“未配置”状态。
