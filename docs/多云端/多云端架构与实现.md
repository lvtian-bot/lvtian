# 多云端架构与实现

> 本文档说明多云端接入架构设计、策略模式应用，以及 WebDAV 的具体实现细节。腾讯云 COS 已在绿天产品改造中退场。

---

## 1. 架构设计与接口契约

系统采用**策略模式 (Strategy Pattern)** 解耦具体云端协议，对外暴露统一的 `CloudService` 门面：

```text
               ┌───────────────────────┐
               │     CloudService      │
               └───────────┬───────────┘
                           │ 调度与门面
                           ▼
               ┌───────────────────────┐
               │    ICloudProvider     │
               └───────────┬───────────┘
                           │
                           ▼
               ┌───────────────────────┐
               │     WebDavProvider    │
               │  (RFC 4918 标准协议)  │
               └───────────────────────┘
```

> **历史变更说明**：早期支持的腾讯云对象存储（TencentCOSProvider）已退场；云存储能力全面收拢至 WebDAV，专门承载闪念笔记（Flash Note）与历史文件的流式追加和对账同步。

### 1.1 `ICloudProvider` 标准接口
```typescript
export interface CloudFileItem {
    key: string;
    size: number;
    lastModified: string;
    etag: string;
    isDirectory?: boolean;
}

export interface ICloudProvider {
    uploadFile(key: string, filePath: string, expectedEtag?: string): Promise<{ etag: string; lastModified: string } | void>;
    downloadFile(key: string, downloadPath: string): Promise<{ etag: string; lastModified: string }>;
    getCloudFileContent(key: string): Promise<string>;
    listFiles(prefix?: string): Promise<CloudFileItem[]>;
    deleteFile(key: string): Promise<void>;
    headFile(key: string): Promise<{ etag: string; lastModified: string } | null>;
    signIn?(): Promise<void>;
    signOut?(): Promise<void>;
    createDirectory?(key: string): Promise<void>;
}
```

## 2. 核心 Provider 实现

### WebDAV 协议 (WebDavProvider)
- **标准方法映射**：
  - `PROPFIND` (Depth: 1)：获取指定目录下的文件元数据与 ETag 列表。
  - `PUT`：上传文件内容，携带 `If-Match` 头防止覆盖。
  - `GET`：拉取文件正文。
  - `MKCOL`：递归保证远端父级目录结构存在。
- **多端兼容性**：支持坚果云 (Jianguoyun)、Nextcloud、自建 Synology/NAS 等标准服务。

## 3. 初始化与 Hydration 约束

- `CloudService` 根据 `useSettingsStore` 中选定的存储服务类型实例化 Provider。
- **启动铁律**：由于凭据保存在本地存储与 SecureStore 中，在调用 `cloudService.initProvider()` 前，**必须确保 Store 已完成 Hydration（即 `hasHydrated === true`）**，避免因读取空配置导致误判为“未配置”状态。
- **平稳过渡**：升级后原 COS 用户不会被自动连往 WebDAV，配置状态准确表现为未配置，引导用户配置 WebDAV，且不影响云端已有历史文档。
