# 系统文件任务

状态：待开发的交接草案；文件操作范围与界面方案待确认。

**实施前提**：本任务及所引用需求属于初步想法。如发现不合适、不清晰、相互冲突或成本明显不合理的地方，应及时与用户沟通，说明影响与建议，相关部分确认后再实施，不得自行猜测补全或机械照搬；不受影响且已明确的工作可继续推进。

建议分支：`server-files`。产品依据：[PRD](PRD.md)。前置任务：[服务端与主聊天](服务端与主聊天任务.md)已合并，安卓可以连接实际服务端。

## 1. 交付目标

原笔记标签页接入所连接服务端的真实文件目录，入口使用“系统文件”，首次进入默认打开服务端用户主目录。Linux VPS 和 Windows 服务端均使用所属实例自己的路径，手机不写死 `/root`、`/home` 或 Windows 用户路径。

## 2. 实施前确定的范围

- 明确用户主目录对应的服务端账户；如部署账户不同于日常账户，配置和界面应准确反映实际目录。
- 默认打开位置与允许访问范围分别定义。是否允许访问主目录之外的位置、如何处理无权限目录，在实现前明确。
- 确定首版预览类型与下载行为。上传、编辑、移动、重命名、删除不自动沿用旧云端文件管理操作，需分别确认是否进入本次范围。
- 展示文件标签、路径导航、加载、无权限、断线和空目录的具体界面方案及文案后实施；空目录与读取失败应有不同表现。

## 3. 开发范围

- 服务端提供当前实例的主目录信息、目录列表、约定范围的文件内容或下载能力，校验路径、权限与访问边界。
- 安卓保留可用的列表与预览组件，替换旧 COS／WebDAV 通用文件浏览的数据链路；服务端目录不进入闪念的 WebDAV 同步队列。
- 支持约定范围内的目录进入与返回、刷新、文件预览和下载；来自聊天的文件入口与文件页使用同一实例和路径语义。
- 处理 Linux 与 Windows 的路径分隔、根目录和名称差异；符号链接等路径解析不能绕过已约定访问范围。
- 浏览、预览或下载不应附带写入或删除远端文件的行为；不将整个服务端目录镜像到手机。
- 配套清理被替换的旧通用笔记导航与无用代码，保留闪念仍使用的 WebDAV、编辑与预览能力。

## 4. 验收条件

1. 安卓连接真实服务端后，首次进入打开该服务提供的用户主目录；目录内容与机器上的实际内容一致。
2. 验证目录进入与返回、刷新、中文名称、空目录、无权限、文件消失与断线等场景。
3. 约定文件类型可预览、下载并交由系统打开或分享；不支持的类型准确提示。
4. 不出现旧云端目录、手机缓存路径与服务端路径混用，不因文件浏览影响闪念同步。
5. Linux 部署后通过安卓联调；Windows 文件路径与权限行为单独验证。缺少环境时明确列出未完成项。

## 5. 文档与部署

更新技术架构中的文件访问职责、数据流和模块索引，以及对应模块文档与 TODO。服务端接口更新与兼容的安卓版本配套验证，记录各自版本；只有服务端部署成功时，不宣称手机已获得文件能力。
