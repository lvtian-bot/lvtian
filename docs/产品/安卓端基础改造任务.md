# 安卓端基础改造任务

状态：待开发的交接草案；分支尚未创建，界面调整方案待确认。

**实施前提**：本任务及所引用需求属于初步想法。如发现不合适、不清晰、相互冲突或成本明显不合理的地方，应及时与用户沟通，说明影响与建议，相关部分确认后再实施，不得自行猜测补全或机械照搬；不受影响且已明确的工作可继续推进。

建议分支：`mobile-foundation`。产品依据：[PRD](PRD.md)。

## 1. 交付目标

清理已退出范围的 COS 和旧个人待办，保留现有闪念及其 WebDAV 使用链路，为个人助理导航和后续服务端接入做好准备。此任务交付后，保留功能能够独立使用，不要求服务端已上线。

## 2. 开发范围

- 移除 COS 配置入口、Provider、签名工具及无其他用途的依赖和引用；检查启动初始化、设置持久化与默认选项。
- 处理已保存的旧 COS 配置：不得自动使用旧 COS 参数连接 WebDAV，也不得无提示切换后声称已经完成配置；未配置 WebDAV 时准确显示配置状态。不得删除云端文档。
- 核查原 COS 缓存和待上传记录的归属，不得在切换存储方式后自动上传到 WebDAV 或覆盖现有闪念文件。
- 移除从闪念 Markdown 提取个人待办的旧页面、专用操作和不再使用的类型与组件。
- 核查 `FlashNoteInputModal`、`FlashNoteService`、`TodoParser` 和相关编辑、预览调用。共享部分只在确认无保留用途后删除，不改写闪念原文中的 Checkbox。
- 保留现有闪念的记录、时间线阅读、编辑、删除、分享、缓存和 WebDAV 同步链路；保留其实际需要的历史文件、冲突处理和失败提示。
- WebDAV 设置保留，后续用途收缩到闪念及关联历史文件。原通用笔记浏览在系统文件接替前不做深度改造，避免先删后补；原始云端数据继续保留。
- 形成五标签最终导航与设置入口的具体界面方案，说明清理旧待办后的导航、尚未接通能力的表现和后续启用顺序。实施前按仓库规则确认；不得自行决定助理待办与新闻摘要的详细交互。
- 调整现有 OTA 工作流的改动范围判断，只有安卓相关且符合现有发布条件的变更才进入发布；纯文档、纯服务端变更应跳过。保留原生变更需要重新打包的现有约束。
- 保留现有安卓包名、签名与 Expo 更新项目身份；仓库改名不等于更换安装与更新身份。展示名称如需调整，按界面文案规则确认后处理。

`App.tsx`、`src/navigation/`、`src/types/navigation.ts`、`src/screens/CloudRepoConfigScreen.tsx`、`src/screens/MeScreen.tsx`、`src/screens/TodoScreen.tsx`、`src/components/FlashNoteInputModal.tsx`、`src/services/CloudService.ts`、`src/services/TencentCOSProvider.ts`、`src/store/useSettingsStore.ts`、`src/locales/`、`.github/workflows/ota-update.yml`。

## 4. 验收条件

1. 现有 WebDAV 配置仍可使用；未配置和旧 COS 用户状态有准确表现。
2. 闪念新增、阅读、编辑、删除、刷新与失败处理按原有行为工作；云端原文及历史记录没有被清理操作删除。
3. 旧个人待办专用能力退出，原文中的待办文本正常保留；未来助理待办未被误写为已实现。
4. 安卓启动与导航正常，COS 运行代码和无用引用清理完整。
5. 工作流范围判断覆盖纯文档、纯服务端、安卓 JS 和安卓原生变更，不为验证工作流而实际发布正式热更新。
6. 完成受影响的类型检查、代码检查与必要测试；真机行为未验证时如实列出，不以静态检查代替。
