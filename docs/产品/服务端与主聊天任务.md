# 服务端与主聊天任务

状态：待开发的交接草案；核心连接方案和具体界面流程待确认。

**实施前提**：本任务及所引用需求属于初步想法。如发现不合适、不清晰、相互冲突或成本明显不合理的地方，应及时与用户沟通，说明影响与建议，相关部分确认后再实施，不得自行猜测补全或机械照搬；不受影响且已明确的工作可继续推进。

建议分支：`server-chat`。产品依据：[PRD](PRD.md)。前置任务：[安卓端基础改造](安卓端基础改造任务.md)已合并。

## 1. 交付目标

在 Windows 与 Linux 上独立运行同一个助理服务，安卓连接后能够持续聊天、查看执行和处理人工请求。手机离线不主动取消已受理的服务端任务。Linux 版本能够部署到 VPS 并验证实际运行。

## 2. 实施前确定的方案

- 核对当前 dsh 的受支持运行方式、协议、鉴权与会话持久化；以当前依赖实际能力为准，不凭旧项目说明固定版本或照搬接口。
- 设计服务端与安卓的连接、配对或认证流程、凭据归属、错误反馈和重连策略；核心技术路线先达成共识，不自行锁定公网、Tailscale 或中继。
- 明确主聊天的默认会话规则、人工审批、停止执行和连接设置界面，展示具体文案与交互后再实施。
- 确定同仓库中的安卓、独立服务端与可共享协议的位置，以及各自的安装、构建和检查入口；不得为复用类型引入安卓运行时对服务端的依赖。
- 为后续文件能力约定当前实例标识、用户主目录来源与目录访问边界；此任务不要求提前实现整套文件接口。

## 3. 开发范围

- 使用 dsh 提供 Agent 循环、工具执行和会话持久化，绿天负责必要的运行管理与客户端接入，不重复开发引擎。
- 实现独立服务启动、停止、配置加载及实际需要的接口；凭据不进入仓库、日志或部署说明。
- 安卓实现连接配置、历史消息加载、消息发送、回复与工具活动展示、人工请求处理和停止执行。
- 明确消息尚未发送、已受理、执行中、等待人工处理、完成或失败的状态，重新连接后向服务端核实，避免重复发送或误报成功。
- 应用切后台、关闭或失联不等于取消服务端任务；服务进程重启后的实际恢复能力以引擎验证结果为准，不承诺未经验证的自动续跑。
- 每个实例独立保存会话、配置和数据；闪念保留既有 WebDAV 链路，不强行迁入服务端。
- 提供 Linux 与 Windows 的安装、启动、停止和更新说明。VPS 部署先核对已有进程、端口、磁盘与运行账户，不能覆盖现有服务或使用未确认的端口。

## 4. Linux 部署交付

1. 在开发环境验证服务，再按部署方案安装测试实例，明确代码版本、运行账户、数据位置、配置位置和服务地址。
2. 敏感配置与业务数据存放在代码和构建产物之外，更新不覆盖会话与配置。
3. 提供健康检查、日志查看、进程重启和旧版本回退方式；正常重启后原有数据可读。
4. 从安卓实际使用的访问路径验证连接，不能只验证 VPS 本机可访问就认定手机可用。
5. 正式部署使用明确版本的发布产物或干净检出；合并与替换正式服务仍遵守既有授权边界。

## 5. 验收条件

- 正常聊天、流式回复、历史恢复、人工审批和停止操作完整可用。
- 覆盖手机断网、关闭 App、重新连接、重复提交与失效审批，页面状态与真实任务状态一致。
- Linux 服务启动、停止、重启和数据保留通过；VPS 上实际部署与安卓远程连接通过。
- Windows 使用原生环境验证安装、启动、停止、重启和数据保留；未完成时明确标记该平台待验收。
- 安卓代码检查与服务端检查分别通过。若安卓或 Windows 运行环境不可用，列出具体未验证项，不能标为全部完成。
