# 云优先架构与按需缓存

> 核心设计原则：云端为主，按需缓存 (Cloud-First, Cache-On-Demand)
>
> **架构演进说明（系统文件与纯在线网盘）**：
> 本文记录早期基于本地沙盒永久缓存与影子系统的设计。随独立服务端上线，底部第 5 标签已重构为直连服务端真实目录的“系统文件”(`ServerFileScreen`)；云盘文件迁移至纯在线的 `CloudNoteScreen`，不再管理本地永久缓存与离线双向冲突队列。最新设计请参见 [docs/系统文件/系统文件与在线网盘.md](../系统文件/系统文件与在线网盘.md)。

---

## 1. 核心设计理念

**“列表即菜单，点击即下单。”**

绿天的文件浏览页 (`NoteScreen` / `BrowserScreen`) 被设计为**云端对象存储的直接视窗映射**，而非本地磁盘文件系统的镜像。

- **唯一真相来源 (Single Source of Truth)**：云端对象存储 (Tencent COS / WebDAV)。
- **列表渲染**：仅依赖云端返回的文件列表。
- **本地缓存**：仅作为“上次已知状态”用于加速首屏秒开，不参与核心状态决策。

---

## 2. 三层交互详细设计

### 2.1 列表渲染层 (View Layer)
**严禁在列表加载过程中遍历扫描本地文件系统！**
1. **读取缓存**：进入页面时，从 `AsyncStorage` 读取上次保存的云端列表快照，毫秒级直接呈现给用户。
2. **静默网络请求**：后台调用 `cloudService.listFiles()` 获取云端最新真实列表。
3. **更新视图**：云端返回成功后，直接覆盖当前列表并更新快照。
4. **禁止行为**：
   - 禁止调用 `FileSystemService.readDirectoryAsync` 遍历本地沙盒目录拼凑列表。
   - 禁止强行对本地和云端列表进行前端 Merge，避免状态死锁与并发竞争。

### 2.2 文件交互层 (Action Layer)
将本地物理文件的存在性校验推迟到用户点击交互的瞬间（Lazy Check）：
1. **用户点击列表项**：
2. **本地命中 (Hit)**：调用 `fsService.exists(path)`，若本地存在，直接进入 `PreviewScreen`。
3. **本地未命中 (Miss)**：
   - 界面弹出加载指示器。
   - 调用 `syncService.performDownload(path)` 异步下载。
   - 下载完成立即跳转预览；若网络不可达则给出清晰错误提示。

### 2.3 单向数据流向 (Unidirectional Data Flow)
所有针对文件的操作（删除、重命名、移动），必须优先确保云端操作成功，再清理本地并刷新列表快照：
- **删除**：云端执行删除 -> 本地清理缓存文件与影子文件 -> 刷新列表。
- **重命名/移动**：云端执行 Copy + Delete -> 本地重命名 -> 刷新列表。
